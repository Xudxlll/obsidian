## 1. 项目目标

本项目计划在百度千帆平台上搭建一个投资顾问类智能体。第一阶段先做一个较简单、可控、可调试的 MVP：

```text
一个主 Agent + 知识库 + 工作流
```

后续再逐步升级为多智能体协同 Agent，对齐千帆推荐应用中的“投资顾问 Agent”形态，即由多个专业子 Agent 协作完成基金对比、基金深度分析、持仓诊断、个人理财辅助等任务。

第一阶段的目标不是直接做一个万能投资顾问，而是先做一个：

```text
行业投资研究顾问 Agent
```

它的核心能力包括：

1. 基于市场环境、国内外局势变化、宏观政策和产业趋势，动态分析并推荐值得关注的行业。
2. 支持行业研究，通过多维度数据收集与分析，生成行业深度报告。
3. 基于研究结果，输出投资方向、配置思路、策略参考和风险提示。

## 2. 平台形态选择

百度千帆官方文档中，Agent 开发主要包含三类形态：

| 类型           | 特点                               | 适合场景            |
| ------------ | -------------------------------- | --------------- |
| 自主规划 Agent   | 主要依靠大模型自主思考和规划完成任务               | 灵活问答、开放式任务      |
| 工作流 Agent    | 每轮对话严格按照工作流执行，可控性更强              | 高可控、复杂业务流程      |
| 多智能体协同 Agent | 由规划主 Agent 拆解任务，再分配给多个子 Agent 协作 | 深度研究、复杂分析、跨任务协同 |

本项目第一阶段建议选择：

```text
工作流 Agent
```

原因是投资研究任务天然是流程型任务，需要稳定执行以下步骤：

1. 理解用户问题。
2. 收集市场和行业信息。
3. 检索知识库。
4. 进行宏观与行业分析。
5. 生成行业推荐与评分。
6. 输出深度报告和投资策略参考。
7. 做合规与风险检查。

相比纯聊天式 Agent，工作流 Agent 更适合这种需要可控、可追踪、可调试的金融分析流程。

## 3. MVP 产品定位

### 3.1 Agent 名称

```text
行业投资研究顾问 Agent
```

### 3.2 Agent 描述

行业投资研究顾问 Agent 是一个面向投资研究场景的智能助手，能够结合宏观经济、政策变化、市场环境、行业景气度、估值水平、资金流向和风险因素，为用户提供行业推荐、行业深度研究报告和投资策略参考。

### 3.3 服务边界

该 Agent 只提供研究分析和策略参考，不构成任何证券、基金或金融产品的买卖建议。

必须遵守以下边界：

1. 不承诺收益。
2. 不输出“稳赚”“必涨”“无风险”“保证收益”等表述。
3. 不直接替用户做交易决策。
4. 不给出不带风险提示的单边建议。
5. 数据不足时必须说明“数据不足”或“需要进一步验证”。

## 4. 知识库设计

千帆知识库用于存储专业领域知识，提高智能体在特定场景下的响应准确性。第一阶段建议建立 4 个知识库。

| 知识库名称   | 内容范围                                  |
| ------- | ------------------------------------- |
| 宏观策略知识库 | 利率、通胀、汇率、财政政策、货币政策、信用周期、库存周期、经济周期分析框架 |
| 行业研究知识库 | 新能源、半导体、AI、医药、消费、军工、金融、地产链等行业研究框架     |
| 投资策略知识库 | 资产配置、行业轮动、估值方法、风险收益比、仓位管理、ETF 配置逻辑    |
| 合规风控知识库 | 风险提示模板、适当性原则、禁止承诺收益、免责声明、合规表达规范       |

### 4.1 知识库配置建议

| 配置项 | 建议 |
|---|---|
| 检索策略 | 混合检索 |
| 召回数量 | 5-8 |
| 匹配分 | 先使用默认值，调试后再调整 |
| 网页搜索增强 | 对动态市场分析建议开启 |
| 搜索顺序 | 最新市场变化用网页搜索优先；行业研究框架用知识库优先 |

### 4.2 建议上传的资料

第一版可以先准备这些资料：

1. 宏观分析框架文档。
2. 行业研究报告模板。
3. 各行业产业链梳理资料。
4. 行业评分模型说明。
5. 投资策略输出模板。
6. 风险提示和免责声明模板。

## 5. 工作流整体设计

第一版工作流建议如下：

```text
开始节点
  -> 信息收集节点
  -> 意图识别节点
  -> Query 多轮改写节点
  -> 知识库节点
  -> API/搜索组件节点
  -> 大模型节点：市场环境分析
  -> 大模型节点：行业推荐评分
  -> 分支器节点
      -> 行业深度报告生成
      -> 投资策略建议生成
  -> 合规风控检查节点
  -> 结束节点
```

## 6. 节点配置说明

### 6.1 开始节点

建议设置以下输入变量：

| 变量名 | 含义 | 示例 |
|---|---|---|
| rawQuery | 用户原始问题 | 现在 A 股哪些行业值得关注？ |
| risk_level | 风险偏好 | 低 / 中 / 高 |
| time_horizon | 投资周期 | 短期 / 中期 / 长期 |
| market_scope | 市场范围 | A 股 / 港股 / 美股 / 全球 |
| report_depth | 报告深度 | 简版 / 标准 / 深度 |

### 6.2 信息收集节点

如果用户没有说清楚投资范围、周期或风险偏好，先追问。

可配置话术：

```text
为了给出更合适的行业研究和策略参考，请补充：
1. 你关注 A 股、港股、美股，还是全球市场？
2. 你的投资周期是 1 个月、3-6 个月，还是 1 年以上？
3. 你的风险偏好是低、中、高？
```

### 6.3 意图识别节点

建议设置 3 类意图：

| 意图 | 用户示例 |
|---|---|
| 行业推荐 | 现在什么行业值得关注？ |
| 行业深度分析 | 帮我分析一下半导体行业 |
| 投资策略输出 | 给我一个行业配置建议 |

### 6.4 Query 多轮改写节点

用于把用户的口语化问题改写成适合检索的查询语句。

示例：

```text
用户原问题：现在有什么行业值得买？

改写后：
基于当前宏观环境、政策变化、市场估值、行业景气度和资金流向，分析未来 3-6 个月 A 股值得关注的行业方向。
```

### 6.5 知识库节点

输入：改写后的 query。

选择知识库：

1. 宏观策略知识库。
2. 行业研究知识库。
3. 投资策略知识库。
4. 合规风控知识库。

检索策略：混合检索。

### 6.6 API/搜索组件节点

第一阶段如果没有金融数据 API，可以先使用千帆平台中的搜索组件或网页搜索增强。

后续可以接入：

1. 指数行情 API。
2. 行业估值 API。
3. 宏观数据 API。
4. 新闻舆情 API。
5. 基金/ETF 数据 API。

### 6.7 市场环境分析节点

该节点负责分析：

1. 宏观环境。
2. 国内政策变化。
3. 海外局势变化。
4. 流动性环境。
5. 市场风险偏好。
6. 对不同行业的影响。

### 6.8 行业推荐评分节点

该节点根据评分模型筛选推荐行业。

推荐评分维度：

| 维度 | 权重 | 说明 |
|---|---:|---|
| 宏观环境匹配度 | 15 | 利率、通胀、汇率、周期位置 |
| 政策支持力度 | 20 | 产业政策、财政补贴、监管变化 |
| 行业景气度 | 20 | 需求、订单、价格、库存、产能 |
| 估值性价比 | 15 | PE、PB、PS、历史分位、盈利预期 |
| 资金关注度 | 10 | ETF 流入、机构持仓、成交活跃度 |
| 催化剂 | 10 | 财报、政策、技术突破、事件驱动 |
| 风险暴露 | 10 | 竞争、监管、海外风险、估值泡沫 |

### 6.9 分支器节点

根据用户意图分流：

| 分支 | 触发条件 |
|---|---|
| 行业推荐分支 | 用户想知道哪些行业值得关注 |
| 行业深度报告分支 | 用户指定某个行业要求深入分析 |
| 投资策略建议分支 | 用户要求配置方向或策略参考 |

### 6.10 合规风控检查节点

该节点用于检查最终回答是否存在不合规表达。

检查规则：

1. 是否承诺收益。
2. 是否使用“必涨”“稳赚”“保证收益”等词。
3. 是否缺少风险提示。
4. 是否把研究观点包装成确定性结论。
5. 是否直接给出不适当的具体买卖指令。

如果发现问题，要求模型重写为合规表达。

### 6.11 结束节点

结束节点输出最终报告或建议。

建议每次输出都包含：

1. 核心结论。
2. 分析依据。
3. 推荐方向。
4. 风险提示。
5. 后续跟踪指标。
6. 免责声明。

## 7. 主 Agent 角色指令

可以将以下内容放入主 Agent 或核心大模型节点。

```text
你是“行业投资研究顾问 Agent”，由资深金融分析师、宏观策略分析师和行业研究员的工作方法驱动。

你的任务：
1. 基于用户问题，识别其投资目标、市场范围、投资周期和风险偏好。
2. 结合宏观环境、政策变化、国内外局势、产业趋势、估值水平、资金流向和风险因素，筛选值得关注的行业。
3. 对指定行业进行多维度研究，输出结构化行业深度报告。
4. 基于研究结论，提供投资方向、配置思路、观察指标和风险提示。

重要限制：
1. 你只能提供研究分析和策略参考，不得承诺收益。
2. 不得使用“必涨”“稳赚”“无风险”“保证收益”等表述。
3. 若数据不足，必须明确说明“数据不足”或“需要进一步验证”。
4. 输出投资建议时，必须同时给出风险因素、适合人群和跟踪指标。
5. 事实、推理、观点要分开表达。
6. 不直接替用户做交易决策，不输出具体买入、卖出、加仓、清仓指令。
```

## 9. 开场白与推荐问

### 9.1 开场白

```text
你好，我是行业投资研究顾问 Agent。我可以结合宏观环境、政策变化、行业景气度、估值水平和风险因素，帮你筛选值得关注的行业，并生成行业深度研究报告和策略参考。

本助手仅提供研究辅助和投资策略参考，不构成任何具体金融产品的买卖建议。
```

### 9.2 推荐问

```text
1. 当前市场环境下，哪些行业值得重点关注？
2. 帮我做一份 AI 算力行业深度分析。
3. 如果我是中等风险偏好，未来 6 个月适合关注哪些方向？
4. 请比较新能源、半导体、医药三个行业的投资性价比。
5. 帮我输出一份行业配置策略参考。
```

## 10. 调试用例

搭建完成后，用以下问题测试：

```text
现在 A 股哪些行业值得关注？我是中等风险偏好，周期 3-6 个月。
```

```text
帮我分析一下半导体行业，重点看政策、景气度、估值和风险。
```

```text
如果海外利率下降，对哪些行业是利好？
```

```text
请给我一份 AI 算力产业链的深度报告。
```

```text
我想做长期配置，新能源和医药哪个更适合？
```

检查标准：

1. 是否会追问缺失信息。
2. 是否会区分事实、推理和观点。
3. 是否引用知识库或搜索结果。
4. 是否给出风险提示。
5. 是否避免承诺收益。
6. 是否避免给出不合规的直接买卖指令。

## 11. 后期升级为多智能体

第一阶段跑顺以后，可以逐步拆成以下子 Agent。

| 子 Agent | 职责 |
|---|---|
| 宏观策略 Agent | 分析利率、通胀、政策、地缘局势和市场风险偏好 |
| 行业研究 Agent | 分析行业景气度、产业链、竞争格局和估值水平 |
| 数据检索 Agent | 查询新闻、研报、行情、估值、资金流数据 |
| 基金/ETF 分析 Agent | 对比相关基金、ETF、持仓、费率和风险收益特征 |
| 持仓诊断 Agent | 分析用户已有组合的行业集中度、风险暴露和风格偏离 |
| 风险合规 Agent | 检查输出是否过度承诺、是否缺少风险提示 |
| 报告撰写 Agent | 将各子 Agent 的结果整理成 Markdown 或 HTML 深度报告 |

升级后的结构：

```text
规划主 Agent
  -> 宏观策略 Agent
  -> 行业研究 Agent
  -> 数据检索 Agent
  -> 基金/ETF 分析 Agent
  -> 持仓诊断 Agent
  -> 风险合规 Agent
  -> 报告撰写 Agent
```

## 12. 推荐实施路线

```text
第 1 阶段：主 Agent + 知识库 + 工作流
第 2 阶段：加入搜索/API 数据节点
第 3 阶段：拆出行业研究 Agent、宏观策略 Agent、风控 Agent
第 4 阶段：升级为多智能体协同 Agent
第 5 阶段：接入用户画像、持仓诊断、基金/ETF 对比能力
```
