# 智研投顾 Agent 项目汇报 PPT 逐页内容规划

## 说明

本文档用于规划“智研投顾 Agent”项目汇报 PPT 的逐页内容。当前阶段先不制作 PPT，只先明确每一页应该讲什么，以及每一页适合承载哪些信息。

本版已经按照“单页不拥挤”的原则重新拆分：每一页尽量只讲一个主题，避免把流程、价值、案例、字段和结论塞在同一页里。建议整份 PPT 控制在 40 到 42 页之间，适合面向评委老师做项目完整汇报。

本 PPT 面向评委老师汇报，表达上应兼顾“项目完成度”“技术实现思路”和“金融合规意识”，避免写成纯产品宣传页。

---

## 第 1 页：封面

**页面标题：**

智研投顾 Agent 项目汇报

副标题：面向国内行业、股票与 ETF / 指数的金融研究工作流智能体

**页面内容：**

- 项目名称：智研投顾 Agent
- 团队名称：不写代码队
- 团队成员：徐嘉皓
- 团队口号：人定胜天
- 平台：百度千帆工作流 Agent
- 核心路线：一个主 Agent + 百度搜索 + 广发证券 MCP + 工作流
- 汇报对象：评委老师
- 日期、课程或项目名称

---

## 第 2 页：项目背景

**页面内容：**

- 普通大模型可以回答金融问题，但在投资研究场景中存在明显局限。
- 金融问题往往依赖最新市场信息、政策动态、行业新闻和结构化指标。
- 如果直接让大模型自由回答，容易出现信息滞后、分类混乱或回答边界不清的问题。
- 因此，本项目尝试把“开放式聊天回答”改造成“可控的金融研究工作流”。

---

## 第 3 页：要解决的核心问题

**页面内容：**

本项目主要解决三个问题：

1. 如何区分用户到底是在问行业、股票、ETF / 指数、通用财经事实，还是日常聊天。
2. 如何把搜索结果、MCP 结构化数据和大模型分析能力组合起来。
3. 如何在金融场景中控制合规风险，避免输出具体股票推荐和确定性买卖建议。

---

## 第 4 页：项目目标

**页面内容：**

- 第一阶段目标：搭建一个可运行、可调试、可扩展的智研投顾 Agent。
- 目标不是做一个万能投资顾问，而是先跑通一个可控 MVP。
- MVP 核心路线：

```text
一个主 Agent + 百度搜索 + 广发证券 MCP + 工作流
```

- 最终输出形式：面向用户的行业、股票、ETF / 指数研究分析报告。

---

## 第 5 页：核心能力范围

**页面内容：**

当前 Agent 支持的主要能力：

- 国内行业推荐。
- 国内行业分析。
- 多个行业对比。
- 国内股票分析，但不做股票推荐。
- ETF / 指数查询、分析和对比。
- 其他财经、公司、市场热点问题的联网回答。
- 日常聊天问题直接由大模型回答。

---

## 第 6 页：为什么选择工作流 Agent

**页面内容：**

金融研究不是单步问答，而是一个多阶段流程：

```text
理解用户问题
-> 判断问题类型
-> 搜索最新资料
-> 获取结构化指标
-> 清洗和整理资料
-> 生成研究报告
-> 加入合规风险提示
```

因此，本项目选择百度千帆工作流 Agent，而不是只依赖单个聊天式大模型。

---

## 第 7 页：工作流 Agent 的优势

**页面内容：**

工作流 Agent 对本项目的价值：

- 路径可控：不同类型问题走不同分支。
- 节点可调试：每个节点都能单独查看输入和输出。
- 结果可复用：Query 改写、搜索、整理、指标分析可以模块化复用。
- 风险可控制：可以在股票推荐、最终报告等关键位置加入合规限制。

---

## 第 8 页：系统节点规模

**页面内容：**

当前 Agent 由以下节点组成：

- 27 个大模型节点
- 10 个 MSAP 节点
- 3 个分支器节点
- 2 个代码节点
- 6 个循环节点
- 1 个参数聚合节点
- 2 个信息收集节点
- 1 个消息节点

这一页只做系统规模概览，完整工作流树状图放在后面单独展开。

## 第 9 页：第一层总分流设计

**页面内容：**

总分类大模型只输出 1、2、3、4：

| 输出 | 问题类型 | 后续路线 |
|---|---|---|
| 1 | 国内行业、股票分析、ETF / 指数问题 | 国内金融主线 |
| 2 | 股票推荐类问题 | 合规拦截 |
| 3 | 其他需要联网的金融、行业、公司、商业、经济、时事问题 | 百度搜索 + 大模型总结 |
| 4 | 日常聊天或不需要联网的问题 | 普通大模型回答 |

---

## 第 10 页：股票推荐与事实查询的边界

**页面内容：**

本项目专门区分“股票推荐”和“股票事实查询”：

- 用户要求推荐具体股票、股票名单、投资标的或股票池，进入分类 2。
- 用户只是问某只股票的股票代码、某个代码是哪家公司、某家公司是否上市，进入分类 3。

示例：

```text
推荐几只新能源股票 -> 分类 2
贵州茅台的股票代码是什么 -> 分类 3
```

这个设计可以避免把普通事实查询误判为高风险的股票推荐问题。

---

## 第 11 页：第二层国内金融意图识别

**页面内容：**

当总分类输出 `1` 后，问题进入国内金融主线，并继续细分为五类：

1. ETF指数分析
2. 股票分析
3. 行业推荐
4. 行业对比
5. 行业分析

这一步的作用是：把“国内金融问题”继续拆成更具体的执行路线。

---

## 第 12 页：国内金融意图识别规则

**页面内容：**

五类金融意图的判断规则：

- 出现 ETF、指数、指数基金，进入 ETF指数分析。
- 出现具体股票名称、股票代码、个股分析或个股对比，进入股票分析。
- 询问哪些行业值得关注，进入行业推荐。
- 比较多个行业，进入行业对比。
- 指定某个行业询问现状、前景、风险，进入行业分析。

**页面内容：**

用户输入

## 第 14 页：行业推荐主线流程

**页面内容：**

行业推荐主线流程：

```text
用户问题
-> Query 改写
-> 百度搜索行业机会、政策、热点、景气度
-> 搜索行业相关代表股票
-> 行业资料整理和去重
-> 股票代码提取
-> 广发证券 MCP 查询股票指标
-> 股票指标整理
-> 最终行业推荐报告
```

---

## 第 15 页：行业推荐主线价值

**页面内容：**

行业推荐主线的关键设计：

- 行业推荐内容来自搜索结果，不直接依赖大模型记忆。
- 搜索内容覆盖行业机会、政策方向、市场热点和景气度。
- 股票只作为行业代表公司观察，不作为买卖建议。
- 最终报告以“行业 + 相关股票指标观察”的形式呈现。

---

## 第 16 页：行业分析主线流程

**页面内容：**

行业分析主线流程：

```text
识别目标行业
-> 改写行业分析搜索 Query
-> 搜索政策、产业链、景气度、竞争格局、风险
-> 资料整理、去重、自然段重述
-> 搜索行业相关 A 股代表公司
-> 提取股票代码
-> 广发证券 MCP 查询股票指标
-> 生成最终行业分析报告
```

---

## 第 17 页：行业分析输出重点

**页面内容：**

行业分析报告重点呈现：

- 行业现状。
- 政策和市场热点。
- 产业链与竞争格局。
- 主要机会和风险。
- 相关股票指标观察。
- 风险提示和免责声明。

这一页强调：行业分析不是简单搜索摘要，而是围绕一个指定行业形成研究报告。

---

## 第 18 页：行业对比主线流程

**页面内容：**

行业对比主线的关键不是直接比较，而是先拆开分析：

```text
用户提出多个行业
-> 提取行业列表
-> 分别搜索每个行业资料
-> 分别整理每个行业分析
-> 汇总多个行业的代表股票指标
-> 从政策、景气度、产业链、估值、风险等维度横向比较
-> 输出对比结论
```

---

## 第 19 页：行业对比设计原则

**页面内容：**

行业对比主线遵循三个原则：

- 先分别分析，再横向对比。
- 对比维度尽量统一，避免 A 行业讲政策、B 行业讲股票、C 行业讲情绪。
- 不输出确定性投资结论，只给研究分析和风险提示。

## 第 20 页：股票分析主线

**页面内容：**

股票分析适用问题：

- 分析某只股票。
- 查询某只股票的基本面、估值、风险。
- 对比多个个股。

基本流程：

```text
识别股票名称或股票代码
-> 百度搜索公司和股票相关资料
-> 广发证券财务对比分析 MCP 获取指标
-> 大模型整理基本面、估值和风险
-> 输出个股研究分析报告
```

---

## 第 21 页：ETF / 指数分析主线

**页面内容：**

ETF / 指数分析适用问题：

- 分析某个指数或 ETF。
- 对比多个 ETF 或指数。
- 查询主题 ETF、行业 ETF、宽基指数等。

主要使用：

- 热门 ETF 榜单 MCP。
- 沪深指数估值分析 MCP。
- 百度搜索获取相关资讯和市场背景。

输出必须是研究分析，不给买入、卖出、加仓或清仓建议。

## 第 22 页：股票推荐类问题的合规拦截

**页面内容：**

凡是用户要求推荐具体股票、股票名单、投资标的或股票池，系统进入分类 2。

处理方式：

- 不继续搜索并生成股票推荐。
- 直接输出合规提示。
- 引导用户改问行业分析、股票分析、风险分析或研究路径。

示例：

```text
用户：推荐几只新能源股票。
系统：本 Agent 不支持推荐具体股票。你可以改为询问“新能源行业的产业链、风险和代表公司有哪些”。
```

---

## 第 23 页：Query 改写设计

**页面内容：**

用户原始问题往往不适合直接搜索，例如：

```text
新能源行业怎么样？
```

Query 改写节点会把问题拆成更适合搜索的字段：

```json
{
  "industry_analysis_query": "新能源行业 政策 景气度 产业链 竞争格局 风险",
  "stock_discovery_query": "新能源行业 A股 龙头公司 股票代码 代表企业"
}
```

---

## 第 24 页：Query 改写的价值

**页面内容：**

Query 改写节点的价值：

- 把“行业资料搜索”和“股票线索搜索”分开。
- 提高搜索结果的相关性。
- 为后续百度搜索节点、循环节点、代码节点和 MCP 节点提供结构化输入。
- 让后续工作流不直接依赖用户原始表达，而是依赖更稳定的检索 query。

---

## 第 25 页：百度搜索节点的作用

**页面内容：**

百度搜索用于获取：

- 行业新闻
- 政策动态
- 市场热点
- 行业景气度
- 产业链变化
- 风险事件
- 相关上市公司和股票代码线索

搜索节点解决的是“最新信息来源”的问题。

---

## 第 26 页：搜索结果整理逻辑

**页面内容：**

搜索结果不会直接进入最终报告，而是先交给大模型资料整理节点处理。

资料整理节点主要做：

- 去重。
- 合并同类信息。
- 删除无关内容。
- 自然段重述。
- 保留关键事实和时间线索。

这一层的作用是把杂乱搜索结果变成可用于报告生成的干净材料。

---

## 第 27 页：广发证券 MCP 数据源

**页面内容：**

本项目使用广发证券提供的 3 个 MCP 获取金融结构化信息：

| MCP 名称 | 主要用途 |
|---|---|
| 热门 ETF 榜单 MCP | 获取热门 ETF 榜单信息，用于 ETF 方向观察和分析 |
| 沪深指数估值分析 MCP | 获取沪深指数估值相关信息，用于指数分析和对比 |
| 财务对比分析 MCP | 获取股票财务和估值指标，用于个股分析、行业代表股票观察和财务对比 |

这一页只讲 MCP 数据源，不展开具体字段。

---

## 第 28 页：股票代码提取与格式控制

**页面内容：**

财经 MCP 需要标准股票代码格式，所以必须先从搜索资料中准确提取股票代码。

输出格式：

```json
["SZ300308", "SZ002594", "SH600519"]
```

规则：

- 只提取中国 A 股。
- 最多提取 3 个。
- 必须是 `SZ/SH + 6 位数字`。
- 不能输出港股、美股、基金、ETF 或指数代码。
- 如果无法判断前缀，不输出。

---

## 第 29 页：代码节点的作用

**页面内容：**

代码节点主要用于把上游大模型输出的 JSON 拆成后续节点能使用的变量。

示例：

```python
import json

def main(params):
    raw = params["query_rewrite_result"]
    data = json.loads(raw) if isinstance(raw, str) else raw

    return {
        "industry_search_query": data["industry_search_query"],
        "stock_discovery_query": data["stock_discovery_query"]
    }
```

---

## 第 30 页：代码节点与循环节点的衔接

**页面内容：**

如果要给循环节点使用，代码节点可以输出数组：

```python
return {
    "query_list": [
        data["industry_search_query"],
        data["stock_discovery_query"]
    ]
}
```

关键点：

- 千帆代码节点最后必须返回字典。
- 返回字典后，下游节点才能引用对应输出项。
- 数组可以作为循环节点的输入，让循环节点逐项并行处理。

---

## 第 31 页：循环节点并行处理逻辑

**页面内容：**

本项目中的循环节点主要用于并行运行。

整体思路：

```text
Array 输入
-> 循环节点并行处理每个元素
-> 每轮输出一个局部结果
-> 累加所有局部结果
-> 交给最终汇总节点
```

也就是说，上游节点先输出一个 `array` 数组，循环节点接收数组后，对数组中每个位置的信息同时进行处理，最后把多个处理结果累加在一起输出。

---

## 第 32 页：循环节点适用场景

**页面内容：**

循环节点适用场景：

- 行业对比中，对多个行业分别搜索和整理。
- 对多个搜索 query 批量执行百度搜索。
- 对多个候选对象逐个做资料整理。
- 对多个结果逐条汇总为统一结构。

效率提升点：

- 避免为每个行业手动搭建重复节点。
- 保持每一轮处理逻辑一致。
- 利用并行处理缩短整体运行时间。
- 便于把多个局部结果累加并统一聚合到最终报告节点。

---

## 第 33 页：Prompt 设计分类

**页面内容：**

本项目不是只依赖一个大 Prompt，而是为不同节点设计不同 Prompt：

- 意图识别 Prompt：只输出分类结果，不解释。
- Query 改写 Prompt：把用户问题拆成可搜索 query。
- 资料整理 Prompt：只去重、整理、自然段重述，不做最终结论。
- 代码提取 Prompt：严格输出 `Array<String>`。
- 指标整理 Prompt：把 MCP JSON 转成可读指标说明。
- 通用联网回答 Prompt：根据用户问题复杂度决定简答或深度分析。

---

## 第 34 页：Prompt 设计原则

**页面内容：**

Prompt 设计遵循三个原则：

1. 每个节点只做一件事，避免一个节点同时分类、搜索、总结和推荐。
2. 输出格式要严格，特别是分类节点、代码提取节点和 Query 改写节点。
3. 最终报告节点只做排版、衔接和合规输出，不随意压缩上游内容。

这样可以提高工作流的稳定性，也方便定位某个节点的问题。

---

## 第 35 页：合规风控设计

**页面内容：**

合规规则：

- 不承诺收益。
- 不使用“稳赚”“必涨”“保证收益”“无风险”等绝对化表达。
- 不直接推荐用户买入或卖出股票、基金或 ETF。
- 不给具体买入价、卖出价、加仓、清仓等交易指令。
- 资料不足时降低结论确定性。
- 最终回答必须包含风险提示和免责声明。
