# 爬虫先导课笔记（陈楷锐老师）

## 一、爬虫概述与 AI 时代的变化（19:08 - 19:15）

### 1.1 传统爬虫 vs AI 辅助爬虫

- **传统方式**：自己写代码 → 自己抓包 → 自己写存储逻辑 → 处理报错
- **AI 辅助方式**：分析数据来自哪个数据包 → 把数据包信息给 AI → AI 自动写代码、存储、修 bug
- 爬虫入门门槛已大幅降低：**只要准确抓到包，且包内参数没有加密，后续流程会非常快**

### 1.2 关键概念

- **抓包（Capture Packets）**：通过浏览器开发者工具捕获网页与服务器之间的数据请求
- **curl**：复制数据包的 curl 命令，可转换为 Python 请求代码
- **Agent（智能体）**：如 Claude Code、CodeBuddy 等工具，能自动调用本地资源写代码、运行、修复 bug

## 二、逆向工程与加密（19:11 - 19:15）

### 2.1 什么是逆向

- **逆向**：通过开发者工具找到数据所在的加密包，解密后获取数据
- 负载（Payload）中的参数可能只是**摆设**（形同虚设），也可能经过**复杂加密**
- 大厂（淘宝、美团等）往往有严格的加密算法

### 2.2 加密的特点

- 发送请求瞬间，后台执行脚本对参数进行处理
- 常见加密方式：MD5（算简单的）、非对称加密、时间戳（毫秒级）
- 复制粘贴到本地时，时间戳已过期 → 无法直接复用

### 2.3 应对加密的方法：自动化（Automation）

- 用脚本模拟人的行为：进入页面 → 点击 → 触发数据包 → 捕获数据
- **优点**：无需解密
- **缺点**：速度慢
- 自动化也可以交给大模型接管

## 三、爬虫的法律边界与风控（19:15 - 19:29）

### 3.1 重要原则

| 规则 | 说明 |
|------|------|
| 爬虫本身不违法 | 工具属性，取决于使用方式 |
| **不要爬带国徽的网站** | 强烈不建议 |
| 责任在人不在 AI | 被抓后定责到使用人身上 |

### 3.2 高风险行为（绝对不能做）

1. **绕过平台防火墙/加密**：网站设加密算法 = 明确表示不允许爬取
2. **爬取个人信息**：手机号、邮箱、个人行为轨迹 —— 绝对禁止
3. **爬取商业化的付费内容**：有会员才能看的数据，不能爬下来转卖
4. **高频请求**：写好循环后不设间隔，1 秒上万次请求 → 可能搞崩服务器
5. **转卖数据**：违法

### 3.3 风控规避

- 网站风控系统设有频率限制（如每分钟几十到几百次）
- 超频率 → IP 被封
- 换 IP 可绕过，但**IP 是付费的**，成本高
- **最佳方案**：控制请求间隔（`time.sleep()`），初学者建议设 0.5~2 秒

## 四、爬虫对金融研究生的意义（19:18 - 19:25）

### 4.1 为什么需要学爬虫

- 方法论创新越来越少 → **数据创新**是突破口
- 拿别人拿不到的数据 → 论文更稳
- **时效性**：舆情分析等需要最新数据，不能依赖已有数据库

### 4.2 爬虫的好处

1. **不依赖别人整理的数据**：可根据研究对象自己采集
2. **增加实证广度**：另类数据、新颖数据提升论文饱满度
3. **就业有帮助**：爬虫工程师待遇高，数据分析师也常需要

### 4.3 爬虫的坏处/注意事项

1. 研究生应将精力放在论文和实证上，不要沉迷于技术破解
2. 初学者容易**频率失控**，必须设置好间隔
3. 爬虫只是工具，为研究方向服务

### 4.4 爬虫在金融领域的应用

1. **文本类**：行业报告、招股书、新闻、上下游公开信息（东方财富、同花顺等）
2. **数据类**：量化数据、另类数据（更新频繁，可能需要高频采集）
3. **风控类**：负面信息监控
4. **其他**：基金研究、宏观研究等

## 六、实战案例一：东方财富网研报爬取（19:52 - 20:54）

### 6.1 环境准备

- **Python 环境**：装 Python 语言本身 + 编译器（PyCharm 社区版 / VS Code）
- **浏览器**：推荐 Google Chrome（开发者工具集成好）
- 目前可以用 AI 工具替代本地环境

### 6.2 第一步：打开开发者工具

三种方式：
1. 右键 → 检查
2. 按 F12
3. 右上角三个点 → 更多工具 → 开发者工具

切换语言：开发者工具设置 → Preferences → Language → 中文

### 6.3 开发者工具各栏目说明

| 栏目 | 功能 |
|------|------|
| **元素（Elements）** | 页面 HTML 结构、跳转链接 |
| **控制台（Console）** | 调试用（入门阶段用不上） |
| **源代码（Sources）** | 页面从打开到渲染完成的脚本链路 |
| **网络（Network）** | 监听所有数据包，**爬虫最主要用这个** |

### 6.4 第二步：定位数据包

1. 打开 Network 面板后**刷新页面**（否则面板为空）
2. 点击放大镜搜索图标，输入**关键词**搜索
3. **技巧**：
   - 用**有区分度的个别关键词**搜索，不要用整句话（可能有样式包裹导致搜不到）
   - 搜到多个结果时，通过**响应内容**确认是否包含完整列表
   - 搜索前先**清除监听记录**（避免缓存干扰）

### 6.5 第三步：验证数据包

1. 点击数据包 → 切换到**响应（Response）**标签
2. 在响应内容中 `Ctrl+F`（Windows）或 `Cmd+F`（Mac）搜索
3. 确认列表中其他条目也存在 → 说明这个包包含完整列表数据

### 6.6 第四步：分析参数

**载荷（Payload）中的参数分析**：

| 参数 | 分析 | 结论 |
|------|------|------|
| `cb`（callback） | 去掉后报 400 错误；设为空值也能跑通 | **必须存在，但内容任意** |
| `keyword` | 搜索关键词，改动后数据变化 | **核心参数** |
| 时间戳 | 去掉后仍能获取数据 | **可有可无**（此网站对时间校验不严格） |
| `pageSize` | 默认 10，可改成 20/50 | **可调整**（需测试网站是否允许） |
| `pageIndex` | 页码，从 1 开始 | **翻页控制** |

### 6.5 参数加密判断方法

- 去掉某个参数 → 代码报错 → 参数必须携带
- 去掉某个参数 → 正常运行 → 参数可有可无
- 修改参数内容 → 正常运行 → 参数不参与加密逻辑
- 修改参数内容 → 报错 → 参数经过加密生成

### 6.6 第五步：转换为代码

1. 在目标数据包上**右键** → 复制 → **以 cURL 格式复制**
2. 粘贴到 **curl 转 Python 工具网站**（老师会提供）
3. 选择 Python 语言 → 生成 requests 代码

### 6.7 第六步：交给 AI 执行

1. 打开 Claude Code / CodeBuddy / Cursor 等 AI 编程工具
2. 粘贴生成的代码，发送指令：**"请你获取数据并存入 CSV"**
3. AI 会自动：写代码 → 运行 → 检查结果 → 修复 bug
4. 如需翻页：告知 AI "翻页获取所有数据"
5. 如需批量：告知 AI "我有一个 Excel 文件，帮我读取关键词批量爬取"

### 6.8 批量爬取思路

1. 确认关键词参数可控（改关键词能获取不同数据）
2. 准备关键词列表（Excel 文件）
3. 告知 AI：读取 Excel → 循环修改关键词 → 逐条请求 → 存储到文档
4. **必须设置时间间隔**（`time.sleep()`）

### 6.9 关键提示词模板

```
请你获取数据并存入 CSV
帮我翻页获取所有页的数据
帮我把关键词独立出来，后续我输入一个关键词就能自动获取所有数据
设置好时间间隔
我有一个文件，帮我把里面的关键词读出来批量爬取，存到一个文档里
```

## 七、实战案例二：汽车之家数据爬取（20:56 - 21:19）

### 7.1 案例特点

- **无传统翻页**：下拉自动加载
- **多层级数据**：品牌 → 车型 → 价格区间 → 级别
- 数据可用于金融实证研究（拓宽数据广度）

### 7.2 爬虫核心思路：从单页到多层

```
单页获取 → 找到品牌控制参数 → 外层套循环（品牌遍历）→ 再外层套循环（字母分类）
```

**原则**：先搞定单一页面的数据获取，再逐层向外套循环

### 7.3 第一步：找到品牌控制参数

1. 点击某个品牌（如奥迪）→ 触发数据包
2. 搜索车型关键词（如"奥迪A6"）→ 定位数据包
3. 观察 URL 中的数字 ID：**奥迪 = 33，问界 = 609，保时捷 = 40**
4. 结论：通过**后缀数字 ID** 控制不同品牌

### 7.4 第二步：找到其他筛选参数

| 筛选条件 | 参数变化示例 | 说明 |
|----------|-------------|------|
| 价格区间 | `price-25-35` | 25-35万区间 |
| 车型级别 | `level-xxx` | SUV/轿车等 |
| 字母分类 | 特定接口 | 返回该字母下所有品牌 ID |

### 7.5 第三步：多层级爬取逻辑

1. 进入字母分类（如 A）→ 获取该字母下所有品牌的 ID 列表
2. 遍历品牌 ID → 逐个发送请求 → 获取该品牌所有车型数据
3. 可选：添加价格、级别等过滤条件细化数据
4. 交给 AI 处理重复和批量逻辑

### 7.6 关键技巧总结

- **搜索用个别关键词**，不要用整句（可能有样式标签包裹）
- **通过数字比对**确认字段映射（不需要逐字翻译中英文）
- **确保数据穷尽**：按字母 A-Z 顺序、按地区分类等方式遍历，避免遗漏
- **去重容易，补漏难**：宁可有重复，不可有遗漏
- **规律性的爬取**比随意爬取更重要

## 十二、汽车之家：两层接口抓全数据（21:30 - 32:37）

### 12.1 数据为什么感觉少了？

汽车之家的数据分为**两个接口**存储：

| 接口 | 内容 | 示例 |
|------|------|------|
| **接口一：车型列表** | 品牌下的车型（问界M6、M7、M9）及其规格 ID | 接口一返回 M7 的 id=6643 |
| **接口二：规格详情** | 每个车型下具体规格的价格、配置 | 携带 6643+规格ID → 获取四驱版价格 |

### 12.2 完整抓取流程（以问界为例）

```
第一步：获取问界品牌下所有车型的 ID 和规格 ID 列表
    ↓
第二步：用「车型ID + 规格ID」发送请求 → 获取每个规格的价格数据
    ↓
第三步：遍历所有车型 → 拿到问界品牌下所有车的所有规格数据
```

### 12.3 跟 AI 沟通要点

- 告知 AI 这里涉及**两个接口**
- 第一个接口：拿车型 ID 和规格 ID 列表 → 存储到 Excel
- 第二个接口：拿着 ID 列表去循环请求 → 获取完整价格数据
- **只给一个数据包不够，要给两个包让 AI 推断规律**

## 十三、两种数据包类型的区分（38:42 - 42:48）

### 13.1 刷新 vs 点击触发

| 方式 | 特点 | 适用场景 |
|------|------|----------|
| **刷新页面** | 一次性渲染所有内容（左侧品牌、广告、全部车型）→ 数据包多且杂 | 首次探索，不知道数据在哪 |
| **清空后点击按钮** | 只触发与该按钮相关的请求 → 数据干净 | 找规律、精确定位接口 |

### 13.2 数据包格式

- **JSON 格式**：结构化数据，易解析 → **优先找这种**
- **页面渲染格式**：可能混入 HTML 标签 → 不是真正的数据接口

> **技巧**：清空 Network → 点击目标品牌按钮 → 只看到与该品牌相关的请求 → 搜到的 JSON 格式数据包就是目标接口

### 13.3 通用原则

- 涉及翻页、点击触发的按钮 → **清空后点击**，而不是刷新页面
- 如果点击和刷新拿到的包一样 → 两种都可以；不一样 → 以后者为准

## 十四、批量获取所有品牌数据（43:49 - 53:11）

### 14.1 找到所有品牌的接口

1. 在任意品牌页面（如问界）刷新
2. 搜索其他品牌名（如"奥迪""比亚迪""尊界"）
3. 如果某个数据包同时包含奥迪、埃安、尊界等 → 这就是**全品牌接口**
4. 从该接口获取所有品牌的 `id` 和 `name`

### 14.2 三层嵌套关系总结

```
层级一：全品牌接口 → 获取所有品牌的 ID（如奥迪=33，问界=609，尊界=647）
    ↓
层级二：用品牌 ID 发请求 → 获取该品牌下所有车型的 ID（如 M7=6643）
    ↓
层级三：用「车型ID + 规格ID」发请求 → 获取具体规格的价格数据
```

### 14.3 操作流程

1. 拿到全品牌 ID 列表 → 保存到 CSV
2. 告诉 AI：**"这个 id 值需要替换成每个品牌的 id 去循环获取数据"**
3. AI 自动写循环代码 → 批量获取所有品牌的所有车型数据

## 十五、首字母分类的真相（59:32 - 01:02:25）

## 十六、自动化（DP/Playwright）入门（01:16 - 02:01）

### 16.1 为什么需要自动化？

**当 request 请求失效时**：

| 失效原因 | 说明 |
|----------|------|
| **Cookie 含时间戳** | 复制粘贴后时间过期，服务器校验发现时间不对 → 返回错误 |
| **需要登录状态** | 淘宝、拼多多等大厂校验登录态，登录信息与时间绑定 |
| **动态 Cookie** | 5分钟就失效，拿到旧 Cookie 无法持续请求 |
| **加密签名** | 参数经过复杂加密，你不知道各参数如何拼接生成 |

### 16.2 自动化是什么？

- **模拟人的行为**：打开浏览器 → 输入账号密码 → 登录 → 搜索 → 获取数据
- 不参与加密流程，只是在浏览器中**等待服务器返回结果后截取**
- 核心工具：**DP（Playwright）**——控制浏览器自动操作

### 16.3 自动化的优缺点

| 优点 | 缺点 |
|------|------|
| 绕过登录、滑块等复杂加密 | 速度慢（每次启动浏览器） |
| 可处理需要人工交互的场景 | 占用本地资源，生产化需服务器 |
| 可填表单、批量提交等 | 网页元素变更后需重新适配 |
| 可与逆向结合（登录拿 Cookie → 再用 request） | 有被反自动化检测的风险 |

### 16.4 自动化完整流程

```
① 打开登录页面 → 定位用户名输入框 → 清空 → 输入账号
② 定位密码输入框 → 清空 → 输入密码
③ 定位登录按钮 → 点击
④ 登录后跳转到搜索页 → 定位搜索框 → 清空 → 输入关键词
⑤ 定位搜索按钮 → 点击
⑥ 监听目标数据接口 → 截获返回的数据 → 解析并保存
```

### 16.5 如何定位元素：XPath

1. 打开开发者工具 → 点击**元素选择器**（左上角箭头图标）
2. 鼠标移动到目标元素（输入框/按钮）→ 点击定位
3. 在元素栏中**右键** → 复制 → **复制完整 XPath**
4. 将 XPath 粘贴给 AI，告诉它对应的操作

### 16.6 与 AI 的沟通模板

```
请写一个自动化脚本：
- 登录网址：xxx
- 用户名框的 XPath：xxx，值：admin，先清空再输入
- 密码框的 XPath：xxx，值：123456，先清空再输入
- 登录按钮的 XPath：xxx
- 登录后跳转到：xxx 页面
- 搜索框 XPath：xxx，输入关键词"耳机"
- 搜索按钮 XPath：xxx
- 搜索后监听后缀为 /api/item 的接口
- 监听到数据后解析并保存为 CSV
```

### 16.7 核心概念：监听（Monitor）

**为什么监听而不是复制 curl？**

- request 方式：拿到旧参数 → 时间戳过期 → 请求失败
- 监听方式：点击搜索瞬间 → 浏览器用当前有效的 Cookie/时间戳发请求 → 服务器返回数据 → **立即截获**（毫秒级）
- 监听 = **守株待兔**，在数据返回的瞬间就截取

**监听 vs 逆向的区别**：

| | 逆向（Request） | 自动化（DP 监听） |
|------|------|------|
| 原理 | 破解加密逻辑，自己构造请求 | 模拟浏览器，等待服务器返回 |
| 速度 | 快 | 慢 |
| 难度 | 高（需要破解每个网站的加密） | 低（只需定位元素和接口） |
| 通用性 | 差（每个网站一套逻辑） | 好（所有网站原理相同） |

### 16.8 验证码/滑块的绕过方法

1. **人工介入**：让 AI 登录后暂停（`input()`函数），人工完成滑块/验证码，回车后继续
2. **付费工具**：市面上有专门绕过验证码的服务
3. 注意：AI 直接绕过 = 逆向，不一定能搞定，且成本高

### 16.9 Cookie 复用优化

- 不要每次都重新登录（容易被风控）
- 让 AI 写代码**先校验 Cookie 是否失效**
- Cookie 有效 → 直接后续操作；失效 → 才重新登录

## 十七、进阶话题与 Q&A（02:01 - 02:20）

### 17.1 逆向工程入门思路

1. 找到数据包 → 进入 **启动器（Initiator）** 标签
2. 从最底层到最顶层 = 包从 0 到 1 的生成逻辑
3. 在最前方打**断点（Breakpoint）**→ 触发请求时代码会停住
4. 一直往前追溯，找到**明文 → 密文**的生成逻辑
5. 把整段 JS 代码复制给 AI → 让它用 Python 复现

> 逆向是长期技能，每个网站逻辑不同，无法速成

### 17.2 关于 Charles 抓包工具

- 用途：监听手机 APP、电脑客户端、网页的接口
- 适用场景：
  - 某些网站打开开发者工具就**跳转回首页**（反调试）
  - Boss 直聘等批量投简历
  - 客户端软件（如万得终端）的数据抓取

### 17.3 关于登录的判断

| 情况 | 说明 |
|------|------|
| 不登录爬取成功 | 登录只对普通用户有意义，对爬虫没有校验 |
| 发送请求直接报错 | 需要登录 |
| 前 N 条可以，后面不行 | 部分校验，可能需要登录或换策略 |

### 17.4 时间戳的处理

- **简单时间戳**：参数中明文的毫秒时间戳 → 用 Python 生成 `time.time()*1000` 替换即可
- **复杂时间戳**：时间戳+随机数+加密逻辑生成的密文 → 需要逆向追踪生成过程

### 17.5 关于万得（Wind）终端

- 万得提供了 **Python/Java 接口**，直接用接口抓取，无需逆向
- 需要会员账号
- 客户端抓包可用 Charles
- 理论上"看得到就能抓得到"

## 十八、课程总结

### 爬虫技术选型决策树

```
拿到目标网站
    ↓
找到数据包（开发者工具 → Network → 搜索关键词 → 定位接口）
    ↓
复制 cURL → 转 Python → 让 AI 发请求
    ↓
能拿到数据？ ─── 是 → 搞定，可继续做批量/翻页
    ↓ 否
分析失败原因（Cookie？时间戳？登录？加密签名？）
    ↓
如果是简单时间戳 → 用 Python 生成时间戳替换
    ↓
如果涉及登录/Cookie/复杂加密 → 使用 DP 自动化
    ↓
自动化：定位元素 → 模拟操作 → 监听接口 → 截取数据
```

### 最终要点

1. **爬虫核心 = 找到正确的数据包**，后续全部交给 AI
2. **单页 → 品牌遍历 → 字母分类**，由内向外逐层套循环
3. **Request 优先**，速度最快；**DP 兜底**，处理复杂加密
4. **AI 是执行者**，你需要提供元素定位和接口信息
5. **规律你自己找，代码 AI 来写**
6. **安全始终第一**：控制频率、不爬敏感数据、不超过法律边界
