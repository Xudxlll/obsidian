# What is ERC-3643?

# The Security Token Standard

# Definition

ERC-3643 is an Ethereum standard specifically designed for issuing and managing permissioned tokens that comply with regulatory requirements for securities.

Standard Name: T-REX (Token for Regulated EXchanges)

![](images/1e904079c0f5dad507b41482b5b75c998bfbded9c58922ff9c4a295ccbca3a73.jpg)

Status

Final - Ethereum EIP

Key Difference: Unlike ERC-20/721/1155, ERC-3643 embeds compliance logic directly into the token contract, enabling automated regulatory enforcement.

# KYC/AML

Know Your Customer and Anti-Money Laundering verification

• Identity verification (passport, national ID)   
• Address verification (utility bill, bank statement)   
• Source of funds documentation   
• Politically exposed person (PEP) screening   
• Sanctions list checks (OFAC, UN, EU)   
• Ongoing monitoring and periodic re-verification

# Implementation

Onchain identity claims issued by trusted KYC providers

![](images/c990db3d0099956d5dc781d5f905af34df12cd473c12dbbd49a4a2a3aa658f8f.jpg)

# Identity Verification

Onchain mapping of wallet addresses to verified identities

• Identity Registry contract registration   
• Unique identity per investor (ONCHAINID)   
• Claim topics: KYC, jurisdiction, accreditation   
• Trusted issuer signatures on all claims   
• Expiration dates on time-sensitive claims   
• Revocation mechanisms for invalid identities

# Implementation

Each verified investor gets ONCHAINID contract with claims

![](images/525c351800e2a295fb3a0b18fcd4a028f45b74fb78ad4d25f67e34cc8e843787.jpg)

# Transfer Restrictions

Programmable rules enforced at smart contract level

• Country restrictions (allowed/blocked jurisdictions)   
• Maximum number of token holders   
• Minimum holding periods (lock-up)   
• Maximum transaction amounts   
• Accredited investor requirements   
• Trading time restrictions (market hours)

# Implementation

Compliance module checks all rules before transfer execution

# Troubleshooting Guide

# Common Issues & Solutions

![](images/626d271aaae9f55d98f7d58e1ec743e15ce2ba6364c6617b236fd501a0a32f68.jpg)

# Metadata not on Etherscan

• Verify \`tokenURI\` is a public IPFS link.   
• Check JSON for \`name\`, \`description\`, \`image\`.   
• Wait 15+ mins for Etherscan to index.

![](images/22c69f9b97305bc46c6a28e77f733f6266628ff006bfd976491431dd441c5900.jpg)

# Transaction Failing / Out of Gas

• Ensure sufficient test ETH on Sepolia.   
• Check compiler version matches pragma (0.8.20+).   
• Try increasing gas limit in MetaMask.

![](images/d66be07d11f1a66b890ea4c20f7ffc0a8864b625d33e6b3dd9309973f0989298.jpg)

# Contract Deployment Errors

• Connect Remix to MetaMask's "Injected Provider".   
• Verify MetaMask is on Sepolia testnet.   
• Check constructor arguments are correct.

![](images/ee4222c03911925509eb4fb3dde64223928518014af6ad3d87727ca5f703dcf8.jpg)

# Transfer Reverts

• Check recipient is registered in Identity Registry.   
• Verify both parties have required claims (e.g., KYC).   
• Use \`canTransfer()\` function to debug.

![](images/2eb74f4e696d9b6ea81867758fe7b3e48f80b8e95d47ec6fb983e02207a347b6.jpg)

# Identity/Claim Issues

• Check issuer address is in Trusted Issuers Registry.   
• Ensure \`claimTopic\` is in Claim Topics Registry.   
• Make sure claim signature is valid.

![](images/9a2ab6052af5047ac9e837512e6b474fec475dd44581671153d36f57aeb5bb38.jpg)

# General Debugging Tips

• Check Remix console for detailed errors.   
• Use Sepolia Etherscan to inspect transactions.   
• Try the Remix debugger to step through code.
