第三页 (Page 3)

•	主题: ERC-1155 介绍 (Introduction to ERC-1155)

•	多代币标准 (Multi-Token Standard):

•	核心概念: 在一个智能合约中可以管理同质化代币 (fungible tokens) 和/或非同质化代币 (non-fungible tokens)。

•	“一个合约可以同时拥有同质化和非同质化代币。”

•	为什么选择 ERC-1155？(Why ERC-1155?)

•	Gas 效率 (Gas efficiency): 批量转移 (Batch transfers) 可以节省 Gas 费用。

•	灵活性 (Flexibility): 可以在同个合约里混合同质化和非同质化代币。

•	简洁性 (Simplicity): 为所有游戏资产（如货币、物品、角色）使用单个合约。

•	非常适合游戏开发 (Perfect for gaming): 管理货币（同质化）和独特物品（非同质化）在一个地方。

•	以太坊改进提案 #1155 (Ethereum Improvement Proposal #1155):

•	ERC-1155 是一个由以太坊社区提出的标准。

•	ERC-1155 vs ERC-721: 关键区别 (ERC-1155 vs ERC-721: Key Differences):

对比标准 (Comparison Criteria)

ERC-721

ERC-1155

代币类型 (Token Types)

仅非同质化 (Only non-fungible)

同质化 + 非同质化 (Both fungible & non-fungible)

合约结构 (Contract Structure)

每个集合一个合约 (One contract per collection)

一个合约支持所有类型 (One contract for all types)

批量操作 (Batch Operations)

没有原生支持 (Not supported natively)

内建批量转移 (Native batch transfers)

Gas 效率 (Gas Efficiency)

多个转移 Gas 较高 (Higher gas for multiple transfers)

批量操作 Gas 较低 (Lower gas with batching)

用例 (Use Cases)

艺术品、收藏品、证书 (Art, collectibles, certificates)

游戏、多资产系统 (Gaming, multi-asset systems)

复杂性 (Complexity)

更简单，专注于单一功能 (Simpler, focused)

更灵活，更复杂 (More flexible, complex)

•	理解差异有助于选择正确的标准。

•	两种标准都很有用，选择取决于项目需求。

第八页 (Page 8)

•	主题: 连接网站与智能合约 (Connecting Website to Smart Contract)

•	3. Web3 基础 (Web3 Basics):

•	Web3 提供商 (Web3 Provider): MetaMask 作为网站与区块链之间的桥梁。

•	window.ethereum 对象：浏览器中 MetaMask 提供的接口。

•	合约实例 (Contract Instance): 代表已部署合约的 JavaScript 对象，需要合约 地址 (address) 和 ABI (Application Binary Interface)。

•	ABI: 描述了智能合约函数和事件的接口信息，允许外部应用（如前端）与合约交互。

•	函数调用 (Function Calls): 从网站代码调用合约函数。

•	读取 (Read): 通常是免费的（只读链上数据）。

•	写入 (Write): 需要 Gas 费用（如铸造代币、转移代币）。

•	工作原理：连接步骤 (How It Works: Step-by-Step Connection):

•	用户点击连接 (User Clicks Connect): 网站请求 MetaMask 连接。

•	await ethereum.request({ method: 'eth_requestAccounts' })

•	获取合约实例 (Get Contract Instance): 创建合约的 JS 对象。

•	new ethers.Contract( address, ABI, signer ) (使用 ethers.js 库)

•	用户完成游戏 (User Completes Game): 网站检测到胜利条件。

•	if (clicks >= 100) { triggerReward() }

•	调用铸造函数 (Call Mint Function): 调用合约的 mintReward() 函数。

•	await contract.mintReward(player)

•	用户确认 (User Confirms): MetaMask 弹出窗口请求批准交易。

•	用户支付 Gas 并签名。

•	代币铸造 (Tokens Minted): 智能合约执行，代币转移。

•	代币会出现在用户的钱包中。

•	Web3 库 (Web3 libraries): ethers.js 或 web3.js。

•	代码范例：网站集成 (Code Demo: Website Integration):

•	connectWallet() 函数：处理 MetaMask 连接。

•	mintGameReward() 函数：使用合约地址和 ABI 创建合约实例，并调用 mintReward()。

•	重要提示: 从 Remix 获取合约的 ABI。
