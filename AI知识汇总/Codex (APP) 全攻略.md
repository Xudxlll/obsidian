本期视频介绍 Codex App 的完整使用方法。作者认为 Codex App 在 Codex 的多种形态中能力最完整：额度相对更高、功能更全、上手更快，免费账户也可以使用。

安装和首次启动前需要先准备好三个基础工具：

- Git
- Node.js
- VS Code

Codex App 支持 Windows 和 macOS。官网会根据系统自动提供对应安装包。Windows 和 Mac 的主要功能基本一致，但 **Computer Use（电脑自动化）** 目前主要在 Mac 上演示和使用。

首次进入 Codex App 后，需要完成以下初始化：

1. 使用 ChatGPT 账户登录。
2. 选择希望 Codex 帮你处理的工作类型。
3. 选择主要使用场景，例如编程或日常工作。
4. 初始化沙盒环境。
5. 后续可以在设置中继续修改插件、Skills 和使用场景。

### `01:48` 基础使用：项目、任务、沙盒与上下文

Codex App 采用经典三栏布局：

- 左侧：任务列表与项目入口。
- 中间：对话窗口。
- 右侧：多功能区域，例如浏览器、文件、终端等。

#### 项目与多任务并行

使用 Codex 时，可以把本地文件夹添加为项目。项目名称通常就是文件夹名称。每个项目下可以开启多个对话任务，也可以同时运行多个项目任务。

任务状态会在左侧列表中显示：

- 转圈图标：AI 正在工作。
- 绿色标签：等待用户批准。
- 蓝色小点：任务已完成。

Codex 的任务列表适合并行处理多个工作，并在不同任务之间快速切换。

#### 对话管理

左上角可以新建对话：

- Windows：`Ctrl + N`
- macOS：`Command + N`

对话可以归属于某个项目，也可以是不绑定项目的普通聊天。左侧搜索功能可以搜索近期对话标题，但不一定能搜索对话正文。对话标题通常由 AI 根据内容自动生成，也可以手动重命名。归档后的对话可以在设置中恢复。

#### 沙盒与权限控制

Codex 的权限系统围绕沙盒运行。默认情况下，Codex 可以读取和修改当前项目文件夹内的文件，但不能随意修改沙盒外文件，也默认不能联网。

这两个限制不是靠模型自觉遵守，而是通过操作系统级机制实现：

- macOS 使用系统内置的 sandbox 机制。
- Windows 也有对应的系统级约束方式。

如果 Codex 需要联网或访问沙盒外资源，会触发提权申请。权限模式主要有三档：

1. **默认审批**：提权操作需要人工确认。
2. **自动审查**：由小模型先判断风险，低风险自动放行，高风险再请求人工确认。作者最推荐这一档。
3. **完全访问权限**：Codex 可以无视沙盒限制执行更多电脑操作，风险较高，应谨慎开启。

#### 上下文管理与模型选择

对话窗口上方会显示当前上下文使用量。当上下文过长时，Codex 会自动压缩历史，也可以通过斜杠菜单手动触发压缩。

作者建议：复杂任务完成后，与其长期压缩旧上下文，不如新开对话，让 AI 更专注于新任务。

模型区域可以选择思考强度、模型版本和速度模式。快速模式可以提升推理速度，但会消耗更多套餐额度。账户额度可以在设置中查看，通常包含 5 小时限额和周限额。

### `09:04` 画图：内置生图与执行中引导

Codex 内置 AI 生图能力，可在项目中直接生成并替换图片资源。视频中以宠物洗护店网页为例：

1. 发现网页中部分配图不合适。
2. 让 Codex 生成三张店内环境轮播图。
3. 让 Codex 根据地图截图生成可爱清新的门店位置图。
4. 将新图片自动替换到网页中。

#### Steer：执行中引导

当 Codex 执行方向不符合预期时，可以使用 **Steer（引导）** 功能中途纠偏。

示例中，Codex 一开始用 SVG 生成地图，效果很差。作者立即发送新指令，要求调用 AI 生图能力重新绘制，并通过引导按钮让新指令立即介入当前任务，而不是排队等待上一轮执行结束。

相关操作：

- 默认情况下，新输入的指令会排队。
- 点击“引导”按钮可中途接管方向。
- 快捷键：`Ctrl + Enter`
- 设置中可以调整执行中输入指令的默认行为。

作者建议保持默认“排队”，需要纠偏时再手动引导。

### `11:58` 计划模式：先对齐方案，再执行复杂任务

对话输入框旁的加号中包含添加照片、文件、插件和计划模式等功能。开启 **计划模式** 后，Codex 不会立即动手修改，而是先生成工作计划，与用户确认后再执行。

计划模式适合复杂任务，例如项目架构迁移。视频中示例是把项目改造成 Next.js：

1. 开启计划模式。
2. 输入“把项目改造成 Next.js 框架”。
3. Codex 通过问题卡片确认项目形态、样式迁移方式、是否启动本地服务器验证等细节。
4. 用户确认计划后，Codex 开始实施。
5. 修改完成后，Codex 启动内置浏览器进行自动化测试。

计划模式的价值在于：

- 帮助用户和 AI 对齐任务颗粒度。
- 降低复杂任务跑偏概率。
- 先确认步骤，再让 AI 执行。

右侧内置浏览器还支持批注。用户可以直接点选页面元素并留言，让 Codex 根据页面反馈继续修改，例如把空心星星改成实心星星。

### `14:01` 代码管理：Git、回滚与 Worktree 并行开发

Codex App 不是传统 IDE，不提供完整代码编辑体验。它可以查看代码、对代码行批注，但日常代码编辑仍建议配合 VS Code 或其他 IDE。

#### 初始化 Git 与推送 GitHub

开始代码管理前，建议先把项目初始化为 Git 仓库：

1. 让 Codex 创建 `.gitignore`，排除不需要提交的文件。
2. 初始化 Git 仓库。
3. 使用右上角 VS Code 按钮打开项目。
4. 如需备份到 GitHub，可先在 GitHub 创建远程仓库，再把仓库地址交给 Codex，让它完成推送。

之后可以用自然语言让 Codex 完成 Git 和 GitHub 相关操作。

#### 用 Git 回滚错误改动

视频示例中，作者先让 Codex 添加“期望到店时间”字段并提交保存。随后又让 Codex 调整字段位置，但发现效果更差，于是希望同时回滚对话和代码。

完整做法：

1. 使用 Codex 的 **分叉（Fork）** 功能，从满意的对话节点派生一个新对话，去掉后续不满意的对话历史。
2. 使用 Git 找到满意状态对应的 commit id。
3. 让 Codex 把代码回退到该 commit。

这样可以同时回滚对话上下文和代码状态，做到“像没发生过一样”。

#### Git Worktree 并行开发

Git worktree 本质上是基于同一个仓库创建新的分支工作目录。每个 worktree 都是独立文件夹，可以并行开发，互不干扰。

视频中作者创建了两个工作树：

- 一个用于优化客户评价区域。
- 一个用于优化门店信息和地图展示。

两个分支分别开发完成后，再合并回主干。这样可以让多个功能并行推进，避免互相影响。临时分支用完后可以右键移除。

### `19:42` 云端运行：把任务交给 Codex Cloud

Codex 既可以在本地运行，也可以在云端运行。启用云端运行的前提是：代码已经同步到 GitHub。

视频流程：

1. 将本地代码推送到 GitHub，确保远端和本地一致。
2. 在运行模式中关联 Codex Web / Cloud。
3. 在网页端选择对应 GitHub 仓库。
4. 输入任务需求，例如把“期望到店日期”默认值设置为明天早上 9:30。
5. Codex 在云端初始化环境、拉取代码、分析项目并完成修改。
6. 创建 Pull Request。
7. 在 GitHub 审核修改并合并。
8. 回到本地项目，同步远端改动。

作者认为云端运行非常适合外出时使用：没有电脑也可以用手机发起任务，只需要在手机上审批和合并即可。

### `21:41` 记忆系统：AGENTS.md 与全局自定义指令

每次新开对话都是新的上下文，AI 默认不记得之前发生过什么。项目复杂后，如果每次都让 AI 重新理解项目，会很低效。

视频介绍了两种主要记忆方式。

#### 项目级记忆：`AGENTS.md`

在项目根目录创建 `AGENTS.md`，作为 AI 每次对话必读的项目指南。它可以记录：

- 项目背景
- 技术栈
- 目录结构
- 开发规范
- 用户偏好
- 常见注意事项

也可以让 Codex 通读项目后，自动总结项目知识并写入 `AGENTS.md`。

对于复杂项目，作者认为 `AGENTS.md` 基本是必写文件。

#### 全局记忆：自定义指令

在 Codex 设置里的个性化 / 自定义指令中，可以编辑全局 `AGENTS.md`，让规则对电脑上的所有项目生效。

视频中的全局安全规则示例：禁止 Codex 使用脚本批量删除文件或目录；如需删除，应一个文件一个文件删除；如果必须批量删除，则停止操作并让用户手动处理。

#### 实验性记忆

Codex 还提供实验性的“启用记忆”功能，可以从聊天中生成新记忆，并带入后续聊天。但该功能仍处于实验阶段，视频中没有展开。

### `24:41` 插件与自动化：连接外部服务，定时执行任务

Codex 官方插件市场中主要有两类内容：

- 插件：通常由第三方服务提供，把外部服务能力接入 Codex。
- Skills：给 Agent 使用的技能说明书或工作流。

视频中安装了 GitHub 插件和 Gmail 插件，并演示：

1. 让 Codex 读取 GitHub 中 Star 数量前十的开源项目。
2. 生成摘要。
3. 通过 Gmail 发邮件给自己。

之后又把这套流程做成自动化任务：每周五下午 4 点运行一次，并把结果发送到邮箱。

自动化任务可以在左侧边栏查看和编辑，包括：

- 执行频率：每周、每天、每小时等。
- 使用模型：简单任务可用 mini 模型。
- 立即运行：用于测试。

自动化执行过程中积累的经验会写入类似 `memory.md` 的文件，帮助下次执行更稳定。

自动化可以和浏览器自动化、Computer Use 结合，完成更多场景，例如：

- 汇总 Teams 今日聊天记录并生成工作日报。
- 打开网站并点击签到按钮。
- 定时查看项目看板并发送进度简报。

### `27:06` Skills：官方技能、第三方技能与自制技能

Skills 是给 AI Agent 的专业技能包，也可以理解为带目录的说明书。它能把特定工作流、专业能力或输出规范封装起来，让 AI 在执行对应任务时更稳定、更高效。

视频介绍了三种使用 Skills 的方式。

#### 方式一：安装官方 Skills

示例是安装 Remotion Skill，让 Codex 用编程方式生成动画视频。作者让 Codex 生成一个 3D 圆锥摆动画，要求包含受力分析，并让角速度随时间缓慢增大。Codex 调用 Remotion Skill 后，生成了完整视频和网页版编辑器。

#### 方式二：安装第三方 Skills

示例是从 GitHub 下载一个“电子杂志风格网页 PPT” Skill：

1. 下载 Skill 压缩包。
2. 在项目中创建 `.codex/skills/` 目录。
3. 把第三方 Skill 放入该目录。
4. 在 Codex 中用斜杠菜单调用该 Skill。
5. 根据提供材料生成网页版 PPT。

生成结果详略得当、重点突出，还带有动效，适合演讲或视频内容制作。

#### 方式三：自制 Skills

作者以“视频字幕转 Markdown 图文笔记”为例，使用内置的 **Skill Creator** 创建自己的 Skill。

需求包括：

1. 读取字幕文件并转换成 Markdown 笔记。
2. 自动添加标点、划分段落。
3. 在适合截图的位置插入截图占位符。
4. 调用 FFmpeg 在视频对应时间点截图。
5. 用本地图片替换 Markdown 中的截图占位符。

Codex 最终生成了 `SKILL.md` 和配套 Python 脚本。后续只要把视频和字幕放进工作区，再调用该 Skill，就能自动生成图文并茂的 Markdown 教程。

### `32:39` MCP：通过标准化工具箱扩展 Codex 能力

MCP 全称是 Model Context Protocol（模型上下文协议），可以理解为大模型的标准化工具箱。通过 MCP，模型可以连接外部系统、获取信息并执行具体操作。

视频中以 Supabase MCP 为例，为宠物洗护项目增加数据库能力。

#### 配置 Supabase MCP

流程如下：

1. 在 Supabase 创建新项目。
2. 找到连接方式中的 MCP 客户端配置，选择 Codex。
3. 复制提供的 MCP URL。
4. 回到 Codex 设置中的 MCP 服务器，添加流式 HTTP 服务器。
5. 在终端执行 `codex mcp login supabase` 完成授权。
6. 授权完成后重启 Codex。

#### 用 MCP 增加后端功能

作者让 Codex 使用 Supabase MCP 创建预约业务表，并把用户表单写入数据库。Codex 完成了：

- 创建预约表。
- 添加后端接口。
- 使用 PostgreSQL 连接池写入数据。
- 修改前端表单提交逻辑。

随后在 `.env.local` 中填写 PostgreSQL 连接地址，重启服务并测试。表单提交成功后，Supabase 表中可以看到预约数据。

### `36:07` Computer Use：让 Codex 操作电脑

最后一部分演示 Codex 的电脑自动化能力。Computer Use 目前主要在 Mac 上使用。

#### 简单示例：发送聊天消息

作者让 Codex 打开聊天软件，找到老板并发送“你好”。Codex 自动完成操作，并在真正发送前请求用户确认。

#### 复杂示例：读取看板并发送日报

作者给 Codex 一个 GitHub 项目看板地址，要求它：

1. 调用浏览器打开看板。
2. 查看团队工单进度。
3. 汇总项目状态。
4. 生成英文简报。
5. 通过聊天软件发送给老板。

Codex 会申请权限调用 Chrome，并使用虚拟鼠标在后台操作，不会明显占用当前窗口。发送前也会再次请求确认。

之后，作者把这套流程做成每天 17:00 自动执行的定时任务。任务内容包括打开 GitHub 看板、总结进度、通过聊天软件发送给老板。

如果要长期使用自动化任务，建议在设置中开启运行时防止系统休眠。该开关是 Mac 独有，Windows 不需要处理。

## 核心收获

1. **Codex App 适合把 AI 编程、文件处理、浏览器自动化、插件和电脑自动化集中到一个工作台中。**
2. **复杂任务优先使用计划模式**，先确认方案再执行，能减少跑偏。
3. **沙盒和自动审查是日常使用的安全基础**，完全访问权限应谨慎开启。
4. **Git 是和 Codex 协作的基础设施**：提交、回滚、分叉和 worktree 能显著提高试错效率。
5. **`AGENTS.md` 是项目长期协作的关键记忆文件**，复杂项目应尽早建立。
6. **插件、Skills 和 MCP 分别解决不同层面的能力扩展**：插件连接服务，Skills 固化工作流，MCP 接入外部工具和数据库。
7. **自动化和 Computer Use 让 Codex 从“写代码”扩展到“替你操作电脑和处理流程”。**
