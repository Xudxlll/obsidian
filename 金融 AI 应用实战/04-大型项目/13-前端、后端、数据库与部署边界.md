## 浏览器为什么不能直接承担全部任务

浏览器适合输入和展示；模型凭证、数据访问与长时间任务通常需要后端组织。FastAPI 提供后端应用入口，路由把不同 URL 的请求交给处理模块，服务层承接业务逻辑。

MongoDB 中的任务与报告记录类似业务台账；Redis 队列用于短时调度和状态协调；Chroma 用于相似记忆。三种存储的职责不同，不能因为都叫数据库就互相替代。

## 目前能看到的前端材料

frontend 只有 dist，包含构建后的页面与资源，没有提供可按 Vue 组件逐个讲解的源目录。可以从入口和资源了解产物存在，但不能编造不存在的页面源码或说本轮完成前端交互测试。

## Nginx 配置告诉了我们什么

可读 frontend.conf 指定静态文件目录，SPA 路径回退到 index.html，并把 /api 代理到 backend:8000。reverse-proxy.conf 再把普通页面请求转发到 frontend，把 /api/ 转发到后端，并关闭相关代理缓冲、设置较长等待时间。

这能说明预期的入口分层，不能反推出宿主机实际开放端口或服务器已经启动。容器内部 8000 与用户电脑上的 8080 是不同层次，后者要由有效编排配置确认。

## Docker 是环境包装，不是研究算法

Dockerfile.backend 描述 Python 环境、系统依赖、代码复制、入口与后端启动。它尝试把构建依赖和运行环境分开，并提供中文字体和文档导出依赖。

当前 Dockerfile 的 builder 段在 pip install . 之前没有看到复制 pyproject 和源码的步骤，这是需要验证的构建问题。附带的两个 compose 文件是长段编码文本，而不是可直接按普通 YAML 阅读的服务定义；README 所引用 docker-compose.nginx.yml 在当前目录清单中也未见。

因此本教程提供部署概念与检查顺序，不把 README 的一行启动命令当作已经验证能运行的操作手册。

## 实际启动前按什么次序验证

先确认材料可读与依赖完整，再检查配置和数据连接，随后用最小离线或模拟输入测试引擎，再测试任务状态与报告，最后才测并发与长连接。不要一次启动全部服务后只看浏览器是否能打开。

> [!question]- /health 返回 healthy 是否说明金融分析可用？
> 不一定。反向代理的健康入口可以直接返回固定文字，不证明模型、数据库、数据源和分析流程都已工作。健康检查需要分层。
