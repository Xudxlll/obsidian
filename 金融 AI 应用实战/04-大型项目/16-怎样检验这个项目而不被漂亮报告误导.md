## 先分四种成功

**程序成功**是没有异常退出；**流程成功**是必要步骤完成；**证据成功**是关键数据正确且可追溯；**业务成功**是输出对研究任务有用并通过验收。四者不能互相替代。

## 从已确认问题建立测试清单

| 现象 | 已见源码或课堂依据 | 应验证什么 |
| --- | --- | --- |
| 小案例要算 PEG 却缺财务 | 工具与任务不一致 | 缺字段时能否拒绝计算 |
| 角色失败仍有文字报告 | 内部异常变成占位文本 | 是否把失败当作有效输入 |
| 新闻与情绪字段动态命名 | 配置 slug 与总结固定键不同 | 关键材料是否走错入口或被截断 |
| 研究裁决优先于交易员计划 | Runtime 信号选择顺序 | 风险关闭时输出来源是否符合预期 |
| JSON 失败产生默认评级 | summary_agent 兜底 | 页面是否显式显示失败 |
| 指定历史日期却使用当前窗口 | 预加载日期生成 | 是否含未来资料 |
| 图上 critical 不一定重试 | 角色内部 catch 异常 | 故障是否真正传到重试层 |

## 先用离线测试，不要一上来消耗大量调用

构造固定的假行情、财务与新闻样本，覆盖正常、缺失、过期、重复和矛盾输入。把模型返回也替换为固定响应，可以先测试状态合并、轮次、字段映射和失败展示。

这些是建议的下一步验证方案，本轮没有修改或运行项目测试。不要把本教程列出测试计划，误读成所有测试已通过。

## 评价模型时再固定资料和成本

若之后接入真实模型，冻结问题集与数据快照，记录模型与参数、所有请求、工具结果和输出。比较事实错误、遗漏、数值错误、引用与任务完成率，同时报告耗时和调用成本。

如果要评价投资表现，还需要独立策略定义、可交易规则、时间对齐、交易成本和样本外检验。投研报告质量与投资收益是不同评价对象。

## 读不出的部分怎样处理

106 个 ENCZ1 封装文件和前端 dist 是当前材料限制。教程没有解包执行它们，不据此宣称路由、Worker、权限或页面交互已经被完整审计。需要更深验证时，应取得可读原始源码与匹配环境。

> [!question]- 为什么不直接把每个错误都自动修掉？
> 本轮目标是学习与拆解，原始材料要可回溯。修改系统会引入新实现与测试范围，应作为后续独立开发工作，而不是悄悄混入讲义。
