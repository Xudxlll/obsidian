## 这个例子只证明工具可以被标准化调用

《12.高阶Agent.pdf》第 4–9 页给出 finance_server.py 与 finance_client.py。服务端注册 get_stock_price，客户端初始化会话、列出工具，再请求某个 symbol。

返回价格 245.67 和固定时间戳是讲义里的模拟数据。无论你查询什么代码，都不能因此当成真实现价；工具名字写着“实时价格”并不改变内部返回的是常数这一事实。

## 连接顺序为什么不能省略

客户端指定 Python 和服务端脚本，以 stdio 启动子进程；ClientSession.initialize 建立协议会话；list_tools 发现可用能力；call_tool 提交名称与参数；结果回到客户端。

这里没有必要先接语言模型。一个普通程序也能调用 MCP 工具，因此可以先验证协议连接，再在 Agent 中使用。这降低了排错复杂度。

## Schema 是产品说明，不是执行结果

symbol 的类型和必填声明告诉调用方应该传什么；函数内部才决定查询源、时间和失败处理。之后如果替换成真实接口，应同时返回数据来源、报价时间、币种、单位与错误状态。

标准化接口可以让多个应用复用同一取数服务，但不会自动增加数据权限，也不会自动保证网络和服务正常。

## 它与课堂 @tool 有什么关系

本地 @tool 把函数交给所在框架执行；MCP 把能力放在一个可连接的服务端，通过协议发现和调用。二者可以互补，Agent 的工具循环也可以使用 MCP 提供的工具。

## 一次安全的离线复盘

不用启动服务，先在纸上写出请求名称、arguments、预期返回，再检查当 symbol 缺失或为空时谁负责校验。然后指出把模拟结果升级成真实数据服务，需要补哪些字段和异常路径。
