# 数据和K线图片：从价格到像素

返回 [[00 项目总览与学习路线]]。

## 1. 原始数据长什么样？

一行通常对应一个交易日，关键列是日期、开盘价 open、最高价 high、最低价 low、收盘价 close，合称 OHLC。还可能有成交量 volume；本次图片没有把成交量画进去。

例如：`2024-01-02, 10, 11, 9.5, 10.5` 表示当日开盘10、最高11、最低9.5、收盘10.5。真实股票价格以项目的行情快照为准，这个数字只是示意。程序使用 pandas 表格处理数据，可对应 [[Python、数据分析与人工智能/数据分析与机器学习/03-pandas|pandas课程]]。

实际样例是 Yahoo 获取的 AAPL 2023—2025 年调整后日线，保存 752 条行情。Yahoo 路径使用 `auto_adjust=True`。项目也实现了 Tushare A股接口，但此前没有配置 Token 做线上实测；积分不意味着已验证所有接口权限。不要把 Token 写进代码或公开文件。

复权是为处理拆股、分红等公司行为对价格序列的影响；不同来源、不同基准不一定完全一致，未复权缺口可能被误认成形态。项目的 Tushare 路线保存因子并按代码中的基准计算，不能未经核对就说与所有软件前复权一致。

## 2. 一根K线是怎样画出来的？

实体连接开盘与收盘；上下影线表示该段最高和最低。本项目约定红涨、绿跌、灰色平盘。注意不同软件颜色可能相反。

固定规则：每张图 60 根日K，640×640 像素、白底、16像素边距；按日期从左到右等距排列；纵轴按**本窗口**最高最低价加5%留白后线性映射。程序不画文字、均线、成交量或网格。

640×640 和60根**不是K线行业标准**，只是这次实验选定的规则。每张图纵轴分别缩放，使形状更方便比较，但不能从图片恢复绝对股价或真实跨窗口波动率；行情和像素映射另存为CSV/JSON。随意拉伸、改变周期、K线根数或样式会改变模型输入分布，不能保证已有模型仍然有效。

阅读代码：`outputs/kline-image-lab/kline_lab/core.py` 中的 `normalize` 检查数据，`ChartConfig` 保存配置，`render_window` 把一段行情画成图，`build_dataset` 负责划分和滑窗。

## 3. 什么是滑动窗口？

默认先按年份切分，再每隔5个交易日生成一张60日图。例如第1张含第1—60根，第2张含第6—65根，**共享55根**。所以117张图不等于117个独立形态：同一事件可能出现很多次。

2023、2024、2025分别生成39张，共117张。先分年份再滑窗减少跨集合共享K线，但集合内部仍有大量重叠。涉及预测未来收益时，还需要检查标签观察窗口是否跨分区，单靠图片不跨界仍不够。

## 4. 输出文件怎么理解？

- `data/quotes.csv`：实际画图用的行情快照。
- `images/`：无标签的原图；原图没有文字，不代表没有真实日期。
- `mapping/`：每根K线的日期、价格和像素位置，用于把框映回行情。
- `manifest.csv`：图片路径、日期区间、分区、哈希等清单。
- `run.json`：数据来源、设置及样式信息。

读一遍清单，再打开对应图和 mapping，可以理解“表格里的一行”怎样变为“图片中的一根K线”。项目文件说明详见 `outputs/kline-image-lab/README.md`。
