# 一、内建模块概述

## 1.1 什么是内建模块

内建模块英文是 `built-in module`，指的是**直接编译进 Python 解释器内部的模块**。

它们不依赖普通的 `.py` 文件或单独的动态扩展文件。Python 解释器启动后，就已经具备加载这些模块的能力。

例如：

```python

import sys
import builtins

```

在当前使用的 CPython 3.9 环境中，`sys` 和 `builtins` 都属于内建模块。

内建模块仍然是模块，所以通常也使用：

```python

import 模块名

```

进行导入。它们的特殊之处不是导入语法，而是模块的实现和存放位置。

## 1.2 为什么需要内建模块

内建模块通常负责解释器运行时最基础、最底层的能力，例如：

● 获取解释器和运行环境信息。

● 提供 Python 的内置函数、类型和异常。

● 实现导入系统、输入输出、线程和垃圾回收等底层功能。

● 与当前操作系统提供的底层接口进行交互。

其中一些模块是 Python 启动和导入其他模块时就需要使用的，因此不能完全依赖普通 Python 文件实现。

# 二、查看当前解释器的内建模块

## 2.1 `sys.builtin_module_names`

`sys.builtin_module_names` 保存当前 Python 解释器支持的内建模块名称，返回值是一个元组。

```python

import sys

print(sys.builtin_module_names)

```

也可以逐个遍历：

```python

import sys

for module_name in sys.builtin_module_names:
    print(module_name)

```

不同操作系统、Python 版本和 Python 实现，得到的结果可能不同。因此，不应该把某一台电脑上的完整结果当成所有环境都相同的固定名单。

## 2.2 判断指定模块是不是内建模块

可以使用成员运算符 `in` 判断：

```python

import sys

print("sys" in sys.builtin_module_names)       # True
print("builtins" in sys.builtin_module_names)  # True
print("math" in sys.builtin_module_names)      # 通常是 False

```

判断逻辑是：

```text

模块名在 sys.builtin_module_names 中
                ↓
当前解释器把它作为内建模块提供

```

## 2.3 使用 `find_spec()`查看模块来源

`importlib.util.find_spec()` 可以查找模块的导入信息。

```python

import importlib.util

sys_spec = importlib.util.find_spec("sys")
math_spec = importlib.util.find_spec("math")

print(sys_spec.origin)
print(math_spec.origin)

```

在当前 Python 3.9 环境中，结果类似：

```text

built-in
/Library/Frameworks/Python.framework/Versions/3.9/lib/python3.9/lib-dynload/math.cpython-39-darwin.so

```

这说明：

● `sys` 的来源是 `built-in`，属于内建模块。

● `math` 来自 `.so` 动态扩展文件，属于 C 扩展模块，不是当前解释器中的内建模块。

# 三、常见内建模块

## 3.1 `sys`模块

`sys` 用于获取和操作 Python 解释器相关的信息。

常见内容包括：

```python

import sys

print(sys.version)       # Python 版本信息
print(sys.platform)      # 当前系统平台
print(sys.path)          # 模块搜索路径
print(sys.argv)          # 命令行参数
print(sys.executable)    # 当前 Python 解释器路径

```

`sys.path` 与模块导入密切相关。执行 `import` 时，Python 会根据导入系统和模块搜索路径寻找目标模块。

## 3.2 `builtins`模块

`builtins` 模块保存了 Python 默认提供的内置函数、内置类型和内置异常。

例如：

```python

print()
len()
int()
str()
list()
open()
Exception
ValueError

```

这些名字通常不需要导入就能直接使用：

```python

print(len("Python"))

```

也可以显式导入 `builtins` 后访问：

```python

import builtins

print(builtins.len("Python"))
print(builtins.int("10"))

```

因此：

```text

builtins        是一个内建模块
len、int、print 是 builtins 模块中的内置对象

```

“内建模块”和“内置函数”不是同一个概念。

## 3.3 `time`模块

在当前 CPython 3.9 环境中，`time` 位于 `sys.builtin_module_names` 中，属于内建模块。

```python

import time

print(time.time())
time.sleep(1)

```

但是模块是否被编译为内建模块，可能随着 Python 构建方式和运行环境发生变化。判断时应以当前解释器的 `sys.builtin_module_names` 为准。

## 3.4 `gc`模块

`gc` 用于访问 Python 的垃圾回收机制。

```python

import gc

print(gc.isenabled())
print(gc.get_count())

```

常见用途：

● 查看垃圾回收是否开启。

● 获取垃圾回收统计信息。

● 在特殊场景下手动触发垃圾回收。

普通程序通常不需要手动管理垃圾回收。

## 3.5 `itertools`模块

在当前 CPython 3.9 环境中，`itertools` 是内建模块，用于提供高效的迭代器工具。

```python

import itertools

counter = itertools.count(1)

print(next(counter))
print(next(counter))
print(next(counter))

```

输出结果：

```text

1
2
3

```

## 3.6 底层内建模块

有些内建模块的名字以 `_` 开头，例如：

```text

_io
_thread
_imp
_operator
_collections

```

名字前面的 `_` 通常表示它们更偏向 Python 内部实现，普通开发者一般优先使用更上层、更稳定的公共接口。

例如：

```text

底层 _thread    -> 通常优先使用 threading
底层 _operator  -> 通常优先使用 operator
底层 _io        -> 通常通过 open() 和 io 模块使用

```

# 四、内建模块与标准库模块的关系

## 4.1 内建模块属于标准库的一部分

从使用者角度看，Python 自带、无需额外安装的功能通常统称为 Python 标准库。

标准库中又包含多种实现形式：

```text

Python 标准库
├── 内建模块：直接编译进解释器
├── 纯 Python 模块：使用 .py 文件实现
├── C 扩展模块：使用 .so 或 .pyd 等动态扩展实现
└── 混合模块：Python 外层接口配合 C 底层实现

```

因此：

```text

内建模块一定属于 Python 自带能力
Python 自带的标准库模块不一定是内建模块

```

## 4.2 常见模块对比

| 模块 | 主要分类 | 典型实现方式 |
| ---- | -------- | ------------ |
| `sys` | 内建模块 | 编译进解释器 |
| `builtins` | 内建模块 | 编译进解释器 |
| `random` | 标准库模块 | 主要由 `random.py` 实现，并使用 `_random` 底层模块 |
| `json` | 标准库模块 | 主要由 Python 代码实现 |
| `os` | 标准库模块 | Python 封装层配合 `posix` 或 `nt` |
| `datetime` | 标准库模块 | Python 参考实现配合 `_datetime` C 加速实现 |
| `math` | 标准库 C 扩展模块 | 当前环境中由 `.so` 动态扩展文件实现 |
| `requests` | 第三方包 | 需要使用 `pip` 额外安装 |

这张表说明：模块是否需要额外安装、是否属于标准库、是否由 C 语言实现、是否是内建模块，是几个不同的问题。

# 五、`builtins`与`__builtins__`

## 5.1 `builtins`

`builtins` 是一个可以正常导入的模块：

```python

import builtins

print(builtins)
print(builtins.print)
print(builtins.list)

```

如果要明确访问 Python 的内置名字，应该优先使用 `builtins` 模块。

## 5.2 `__builtins__`

在很多代码运行环境中，还可以看到：

```python

print(__builtins__)

```

`__builtins__` 是解释器自动放入全局命名空间的实现细节。在不同运行环境中，它可能是一个模块，也可能是一个字典。

因此，自己编写程序时不要依赖 `__builtins__` 的具体类型。需要访问内置对象时应写：

```python

import builtins

```

而不是依赖：

```python

__builtins__

```

# 六、模块的导入流程

以这句代码为例：

```python

import sys

```

可以把导入过程简化理解为：

```text

执行 import sys
        ↓
先检查 sys.modules 中是否已经加载
        ↓
如果没有，再由导入系统查找模块
        ↓
发现 sys 是内建模块
        ↓
由解释器提供并初始化 sys 模块对象
        ↓
把模块对象绑定到当前作用域中的 sys 名字

```

可以查看当前已经加载的模块：

```python

import sys

print("sys" in sys.modules)

```

`sys.modules` 是一个字典，保存当前程序已经加载过的模块对象。

需要注意：

```text

sys.builtin_module_names 记录当前解释器提供的内建模块名称
sys.modules               记录当前程序已经加载的模块

```

两者含义不同。

# 七、常见误区

## 7.1 Python 自带的模块不一定是内建模块

例如：

```python

import json
import random
import math

```

它们都不需要使用 `pip` 安装，属于标准库，但不代表它们一定是内建模块。

## 7.2 C语言实现的模块不一定是内建模块

`math` 主要由 C 语言实现，但当前环境中的 `math` 来自动态扩展文件，因此属于 C 扩展模块，而不是内建模块。

判断一个模块是不是内建模块，不能只看它是不是 C 语言实现，应查看：

```python

import sys

print("math" in sys.builtin_module_names)

```

## 7.3 `builtins`模块不等于所有内建模块

`builtins` 只是内建模块中的一个。它主要保存 `print()`、`len()`、`int()`、`str()` 等内置对象。

下面两个概念不能混在一起：

```text

内建模块：sys、builtins、gc 等模块
内置对象：print、len、int、str、ValueError 等名字

```

## 7.4 不要固定背诵完整名单

内建模块名单可能因 Python 版本、操作系统和编译方式不同而变化。

更重要的是掌握查询方法：

```python

import sys

print(sys.builtin_module_names)

```

# 八、综合示例

下面的程序可以查看模块是否属于当前解释器的内建模块，并显示模块来源：

```python

import sys
import importlib.util

module_names = ["sys", "builtins", "time", "math", "random", "json"]

for module_name in module_names:
    is_builtin = module_name in sys.builtin_module_names
    spec = importlib.util.find_spec(module_name)
    origin = spec.origin if spec is not None else None

    print("模块名：", module_name)
    print("是否为内建模块：", is_builtin)
    print("模块来源：", origin)
    print("-" * 30)

```

代码运行逻辑：

```text

准备要检查的模块名
        ↓
在 sys.builtin_module_names 中判断模块名是否存在
        ↓
使用 find_spec() 查找模块的导入信息
        ↓
读取 origin 查看模块来源
        ↓
输出判断结果

```

# 九、小结

内建模块是直接编译进 Python 解释器内部的模块。

最重要的知识可以归纳为：

```text

sys.builtin_module_names
    查看当前解释器支持的内建模块名称

模块名 in sys.builtin_module_names
    判断指定模块是不是当前解释器的内建模块

importlib.util.find_spec(模块名).origin
    查看模块来自 built-in、Python 文件还是动态扩展文件

sys.modules
    查看当前程序已经加载的模块

```

几个概念的关系：

```text

内建模块：直接编译进解释器，例如 sys、builtins

标准库模块：随 Python 一起提供，包括内建模块、纯 Python 模块和 C 扩展模块

builtins 模块：保存 print、len、int、str 等内置对象

第三方模块：不随 Python 默认安装，通常需要使用 pip 安装

```

一句话记忆：

> Python 自带的模块属于标准库，但只有直接编译进当前解释器、能够在 `sys.builtin_module_names` 中找到的模块，才是严格意义上的内建模块。
