## 1. 工作流Agent概述

### 1.1 定义

工作流Agent（工作流智能体，以下简称工作流Agent）支持通过工作流编排的形式还原业务流程，每轮对话均严格按照工作流执行，提高了AI应用的可控性，并可编排出复杂业务流程，适用于客服、营销、办公等高可控及高复杂度等场景。

千帆平台提供了一个可视化画布，你可以通过拖拽节点迅速搭建工作流。同时，支持在画布实时调试工作流。在工作流画布中，你可以清晰地看到数据的流转过程和任务的执行顺序。

![](baidu_images/9f654908215b7a8d0bec0cb1fef70938d9502328a59b1edd9c23e993384c0b3b.jpg)

工作流模式的设计初衷是为了满足固定流程场景的需求，弥补自主规划模式因灵活性过强导致的流程不可控问题。传统Agent在处理重复性流程任务时需要标准化响应，工作流模式通过预设流程提升效率，降低复杂场景的开发门槛，无需依赖大模型的自主推理能力即可实现流程自动化，适合业务流程固定的场景。

### 1.2 与自主规划Agent的对比

千帆平台的自主规划Agent和工作流Agent是两种核心的应用开发模式，它们分别侧重于智能决策与流程固化，以适应不同的业务场景。具体对比见下表：

<table><tr><td>对比维度</td><td>自主规划Agent</td><td>工作流Agent</td></tr><tr><td>核心逻辑</td><td>智能驱动:依靠大模型自主进行目标拆解、工具选择和路径规划,动态决策。</td><td>流程驱动:严格按照开发者预设的流程(工作流)执行,每一步都是确定的。</td></tr><tr><td>开发方式</td><td>低代码/对话式:只需设定目标和描述任务,通过提示词引导即可。</td><td>可视化编排:通过拖拽节点(如大模型、API、分支器)来设计和串联业务流程。</td></tr><tr><td>可控性与灵活性</td><td>高灵活性,低可控性:能灵活应对未知和复杂任务,但执行路径不固定,有一定的不确定性。</td><td>高可控性,低灵活性:执行路径完全固定,结果稳定可靠,但难以处理预设之外的情况。</td></tr><tr><td>适用场景</td><td>需求开放、多变、复杂的任务,如:旅游行程规划、行业深度分析报告生成、综合性营销策略设计。</td><td>流程固定、要求严格遵循标准作业程序(SOP,Standard Operating Procedure)的业务场景,如:车险续保引导、简历解析与信息提取、订单预订、改签与退票处理。</td></tr><tr><td>优势特点</td><td>-智能闭环:能自我反思和动态调整任务路径。-资源调度:自动按需匹配和调用各种工具。</td><td>-稳定可靠:有效限制大模型幻觉,保障业务精准执行。-可复用:支持流程的导入导出,便于在企业内部分发和复用。</td></tr></table>

### 1.3 工作流Agent核心特点

模块化：每个功能都是独立的节点，如大模型节点、API节点、知识库节点等，可根据业务需求灵活组合。

可视化：通过拖拽方式连接节点，在可视化画布中清晰呈现业务流程和数据流转。

数据流转：节点之间可以传递数据，前一节点的输出可作为后一节点的输入，形成完整的数据链路。

快速迭代：所见即所得的调试体验，支持单节点调试和整体工作流调试，便于快速验证和优化。

#### 工作流节点介绍：

节点是千帆平台工作流编排的基础功能单元。通过连接并配置不同的节点，可以灵活且稳定地实现业务流程编排。

每个节点承担特定职责，串联起来形成完整的Agent工作流——从接收用户输入，到调用工具、处理数据，最终输出结果。

### 2.2 记忆变量

开发者可根据应用设定记忆变量，应用用户在对话过程中可以录入变量内容，每个变量支持存储一维、单个数据。在对话过程中，应用将依据存储的变量值进行答复。

应用配置中的记忆变量须与工作流中的记忆变量节点配合使用：先在应用配置中添加变量，再通过节点完成读写操作。

#### 具体操作如下：

【应用配置】中的【记忆变量】添加记忆变量：在【应用配置】中点击【记忆变量】，进行记忆变量的添加。

名称：记忆变量的变量名。

填写要求：

仅支持英文、数字、下划线

必须以英文字母开头

50字以内（来源：千帆平台官方文档）

描述：用于对该记忆变量用途进行描述，该描述仅供开发者备注查看，对该变量的读取和写入无影响。最大字符数为400（来源：千帆平台官方文档）。

默认值：当没有对该记忆变量进行写入时，记忆变量的初始化值。

用户数据记录时长：

如选择【永久】，则该应用用户一旦赋予变量值后将会永久存储，不会随着会话关闭而恢复为默认值。

如选择【单次会话】，当一次会话结束后，则应用用户赋予的变量值会自动恢复为默认值，仅对一次会话生效。

![](baidu_images/8bc52147b7db86a8b1ad849c684dd0e636deb73b84338b217c4d819c64808634.jpg)

【节点】中的【记忆变量】使用记忆变量：【节点】中的【记忆变量】有两种功能，记忆变量写入和记忆变量读取，且一个记忆变量节点只拥有读取或者写入功能。即：单个记忆变量节点仅支持 “读取” 或 “写入” 其中一种功能，无法同时完成读写操作。

记忆变量写入： 用户在应用中创建记忆变量后，选择记忆变量写入，可以在工作流节点写入记忆变量。写入调试成功后，输出参数isSuccess值为true，节点写入变量值同步应用中记忆变量值。

若写入调试失败，则输出参数isSuccess值为false。

## 1. 工作流Agent之工作流编排

工作流编排支持通过节点编排的形式决定工作流 Agent 每一步需要执行的任务，应用将会从开始节点起按照编排顺序执行。这种编排方式类似于流程图设计，每个节点负责特定的功能模块，节点间的连接线代表数据流向，形成了完整的业务处理链路。

![](baidu_images/a22581cb0c6545c28d4b625739a15396c55c06331952992ca35bbb7ba13a1803.jpg)

### 1.1 开始节点

工作流运行的起点，开始节点默认导入工作流所需的输入参数，包括用户输入的原始内容、用户与应用的对话历史和用户在应用对话中上传的文件变量，将会自动从用户输入中获取。在进入画布后，画布中会默认包含一个开始节点。开始节点不可以被复制或删除。

#### 1.1.1 参数说明

系统参数：默认带入7个系统参数，可在整个工作流的任意节点被引用。系统参数将更好地帮助应用进行数据传递，这些参数由平台自动填充，开发者无需额外处理即可直接使用。

rawQuery：用户的原始对话消息，这是最核心的输入参数，包含了用户当前轮次提出的问题或指令。

chatHistory：用户与应用的对话历史轮数，由应用配置中对话设置的【参考对话轮数】决定。这个参数对于需要上下文理解的多轮对话场景尤为重要。

fileUrls：用户在应用中上传的文件地址。当前仅支持一个文件上传，可用于需要文件处理的场景，如简历解析、图片识别等。

fileNames：用户在应用对话中上传的文件名称，与文件地址一一对应。（当前仅支持上传一个）

end\_user\_id：终端用户的唯一 id ，使用 API 调用时，支持开发者传入。其他情况下为终端用户在各渠道的唯一标识。这个参数可用于用户行为追踪和个性化服务。

conversation\_id：会话 id ，是会话的唯一标识。同一个用户的多轮对话共享同一个conversation\_id，便于追踪完整对话流程。

request\_id：本次请求的 id ，便于记录与调试。当出现问题时，可以通过request\_id快速定位具体的请求日志。

### 1.2 意图识别节点

意图识别节点可以对输入的语句进行意图分类，并根据配置抽取该语句内的关键参数，匹配到不同的流程分支执行。意图识别是对话系统的核心能力之一，它决定了系统如何理解用户的真实需求。

#### 1.2.1 添加意图识别节点

![](baidu_images/bbf437c4c068e064db522c29890431f2efd5541a19861c55ebbc9b25b3c2f4d7.jpg)

#### 1.2.2 节点配置

模式：意图识别节点有两个模式，分别是"极速模式"和"精确模式"。

极速模式：适用于意图明确且简单，对响应速度要求高的场景，不支持配置意图例句和参数抽取。极速模式通过轻量级模型快速判断，响应时间通常在毫秒级。

精确模式：适用于多意图复杂场景，支持配置意图例句并进行参数抽取，耗时相对较长。精确模式能够处理更复杂的语义理解任务，可以识别用户语句中的实体信息。

输入参数：节点将根据输入参数 query 进行意图识别和匹配。输入参数 query 支持引用前序节点的输出变量（如开始节点的 rawQuery ）或手动输入字符串，变量类型为 string 。

意图配置：极速模式意图配置包括意图名称和意图描述，精确模式意图配置包括配置意图名称、意图描述、意图例句、和需要抽取的参数。

#### 极速模式配置

意图名称 & 意图描述：大模型将根据意图名称和意图描述来进行意图分类，在配置时清晰明确表述意图，能够获得更好的识别效果。

即使是极速模式，意图描述的准确性也至关重要。好的意图描述应当包含"是什么"和"不是什么"的边界说明，例如"查询天气：用户询问天气情况，不包括询问气候特点和气象原理"。

![](baidu_images/9ce604a2d737fbbb4f5e21db38a6ab66219384edda46bf146824339702efc640.jpg)

#### 精确模式配置

意图名称 & 意图描述：大模型将根据意图名称和意图描述来进行意图分类，在配置时清晰明确表述意图，能够获得更好的识别效果。

意图例句：意图例句可以帮助进行意图识别结果的调优，您可以通过配置意图例句，来模拟用户在该意图下可能的输入情况，使意图识别结果更准确。例句越丰富、越贴近真实用户表达，识别效果越好。

参数抽取：参数抽取可配置识别到该意图时需要抽取的参数。可通过配置参数名、参数类型、参数描述来定义参数。配置后，执行意图识别节点，分类到该意图时，大模型会根据参数描述进行相应的参数抽取并输出对应值。例如在"查天气"意图中，可以抽取"城市"、"日期"等参数。

![](baidu_images/8cca5252bffa4b44bcc40eb0e62e2187ebdbc6511f44ad6da0f35bbfee03ef48.jpg)

高级配置：高级配置支持对执行该意图分类的模型进行相关配置。

模型选择：选择执行该意图分类任务的大语言模型。不同模型在理解能力、响应速度、成本等方面存在差异，应根据实际需求选择。

对话历史：开启后，将会引用用户与应用的对话历史作为意图识别的输入信息（对话历史轮数由应用配置中的【参考对话轮数】来决定）。对话历史默认关闭。在多轮对话中，开启此功能可以让意图识别更准确，例如根据前文指代关系确定当前意图。

\- 针对“千帆”产品的功能、使用方法、收费等具体问题。

\- 示例：千帆是什么；千帆怎么收费；千帆的知识库怎么用。

> 2. 非产品使用的问题

\- 包括闲聊、常识问答、趣味话题、个人看法类提问等非产品相关问题。

> 3. 天气查询

\- 用户明确询问当前或未来某地的天气情况。

\- 示例：今天北京天气怎么样；明天上海会下雨吗；广州的气温是多少？

\- 仅输出对应意图的数字序号（1、2 或 3），不添加任何解释、标点或额外内容。

### 1.3 节点配置

输入参数：参数名不可修改，参数类型为 String，上级节点的输出参数会强制转换为 String 类型作为知识库节点的输入，输入参数有两种类型：

引用类型：引用上一个节点的输出变量（最常用）

常量类型：可以输入一个 String 类型的入参（用于测试或固定查询）

选择知识库：选择需要检索的知识库，支持同时选择多个知识库，但是有一个重要约束：需要保证知识库节点中的多个知识库必须属于相同的向量模型，确保向量空间一致，才可以进行统一检索。这是因为不同模型产生的向量处于不同的“语义空间”，无法直接进行相似度计算。若强制混合，会导致检索结果混乱、不可用。建议在创建知识库时统一规划向量模型。

检索策略：按照指定的检索策略从知识库中寻找匹配的片段，不同的检索策略可以更有效地找到正确的信息，提高最终生成的答案的准确性和可用性。

<table><tr><td>检索策略</td><td>原理说明</td><td>适用场景</td><td>优缺点</td></tr><tr><td>混合检索</td><td>同时使用倒排索引(关键词匹配)和语义检索(向量相似度),综合两种策略结果</td><td>大多数通用场景</td><td>优点:综合效果最优;缺点:计算成本较高</td></tr><tr><td>语义检索</td><td>将Query和知识片段都转为向量,计算向量相似度,理解语义而非字面</td><td>意图理解、同义词替换、概念关联场景例:&quot;苹果手机&quot;与&quot;iPhone&quot;</td><td>优点:理解能力强缺点:对罕见词效果差</td></tr><tr><td>全文检索</td><td>传统的关键词匹配,使用倒排索引技术</td><td>精准匹配场景例:产品型号、订单号、法律条款</td><td>优点:精确匹配强缺点:无法处理同义词</td></tr></table>

召回数量：设置从知识库中召回与输入 Query 匹配的知识片段的个数，设定的数量越大，召回的片段越多。召回数量的选择需要在信息全面性和处理效率之间权衡。过少，可能遗漏关键信息；过多，引入噪声，增加Token 消耗，降低响应速度。

匹配分：在检索过程中，用来计算输入 Query 和知识库片段的相似度，高于匹配分数的片段将会被检索召回。匹配分阈值越高，召回的片段相关性越强，但可能漏掉部分相关内容；阈值越低，召回的片段越多，但可能包含噪声。可根据业务场景反复测试找到最佳值。

匹配分与召回数量的协同作用：匹配分决定了召回的“质量底线”，召回数量决定了召回的“数量上限”。两者共同作用于检索结果：先通过匹配分过滤低相关片段，再按相似度排序取前N个（召回数量）。实践中建议先设置一个较高的匹配分（如0.3-0.5）保证质量，再根据实际效果调整召回数量以补充信息量。

拓展上下文信息：采用 Small-to-Big 策略，提升 RAG（检索增强生成）的能力。

o Small-to-Big 策略：先检索小片段（精确），再扩展到大片段（上下文）

工作原理：命中某个小切片后，将其前后的邻居切片一并返回

效果：让大模型获得更完整的上下文信息，理解更准确

代价：会增加召回切片内容，导致模型输入 Token 数量增加、降低模型响应速度、增加成本消耗。

### 循环类型

循环节点支持两种循环类型：数组循环和条件循环。

数组循环：适用于遍历一个数组，并对数组中的每个元素执行相同操作的场景。比如：

客户反馈处理：针对一批客户与客服的对话，进行分析与处理，识别出对话中需要改进的问题。

多 query 检索：对前序改写出来的一组 query 都进行知识库/百度搜索，最后整体进行排序。

条件循环：会默认一直循环，直到满足跳出循环的条件，或达到最大执行次数（1000次）。它适用于需要动态判断是否重复执行流程的场景，比如：

客户信息收集：在业务办理中，需要判断必须收集的信息是否已经收集完整，如果收集完整可以进入下一步流程，如果未收集完整，则需要一直追问。

游戏规则设定：多轮游戏中，需要判断当前是否满足游戏结束条件，如果不满足则继续进行，如果满足则进入下一阶段。

### 输出参数配置

<table><tr><td>模式</td><td>行为</td><td>适用场景</td></tr><tr><td>最新值</td><td>获取每次循环的最新结果</td><td>需要在循环内引用前次结果</td></tr><tr><td>累计值</td><td>以数组形式存储所有结果</td><td>需要收集所有循环结果</td></tr></table>

输出参数可以在循环内的节点中被引用。例如，若需在第 n 次循环中使用第 n-1 次循环的结果，可将输出参数设置为“最新值”，并在相应节点直接引用。若需保留所有循环迭代的结果，则可将输出参数设置为“累计值”，系统将自动以数组形式存储并累积每次迭代的结果。

用户可为输出参数设置初始值，该值将在首次进入循环时被使用。初始值可引用前序节点的输出结果，或由用户手动配置。在手动配置时，请确保填写的参数值类型与预期一致。

### 跳出循环节点

跳出循环节点的功能类似于编程语言中的 break 语法效果。通常与条件循环和分支器节点配合使用，用于在满足特定条件时终止当前循环，并直接进入下一个节点。 例如，在循环过程中，若某次迭代的结果满足预设的终止条件（如达到目标阈值、出现特定事件或满足特定逻辑判断），则触发跳出循环节点，结束循环流程。

跳出循环节点只能添加在循环节点中使用，无需连接后续节点，也不用连接到继续循环。

## 1. API 节点

### 1.1 API节点概述

API 节点是百度千帆智能体工作流中对接外部数据服务与业务系统的核心执行类组件，作为智能体与外部环境交互的标准化桥梁，支持通过可视化配置，调用符合 RESTful（REST，表述性状态转移）风格的HTTP外部应用程序编程接口，实现外部数据获取与服务调用。

该节点无需复杂代码开发，仅需完成接口地址、请求参数、权限鉴权等基础配置，即可让智能体突破平台原生能力与大模型知识边界，连接第三方公开服务或企业内部私有系统，获取外部数据并回传至工作流后续节点。

### API 节点核心价值

### 打破知识局限，获取实时专属数据

弥补大模型知识更新滞后、无外部私有数据权限的短板，支持获取实时动态数据（天气、股票行情、新闻等）与企业内部业务数据（订单、客户、库存等），全面拓宽智能体能力边界。

### 零代码配置，实现灵活外部对接

采用可视化配置模式，无需编写底层对接代码，即可适配各类标准 API 接口，既能对接第三方公开服务接口，也可接入企业内部私有业务系统，适配多元化业务对接需求。

### 自定义程度高，满足个性化需求

相较于平台预置工具节点与 MCP（Model Context Protocol，模型上下文协议） 服务节点，API 节点不受预制功能限制，可根据实际业务需求，对接专属定制化接口，满足企业个性化智能体开发与业务系统联动需求。

### 多节点联动，构建复杂自动化流程

可与循环节点、大模型节点、分支器节点高效联动，例如搭配循环节点实现批量 API 调用，结合分支器节点实现结果判断分流。

### 典型应用场景

## 2. 参数聚合节点

### 2.1 参数聚合节点概述

参数聚合节点是百度千帆智能体可视化工作流中，专用的参数整合类流程辅助组件，核心作用是汇总工作流内多个分支路径的输出参数，建立统一的参数输出入口。该节点具备分支结果自适应适配能力，无论多分支工作流中哪一条分支被触发执行，其有效输出结果均可被该节点捕获整合，最终输出标准化统一参数，供下游所有节点直接调用。

参数聚合节点不参与业务逻辑执行与数据计算，仅专注于参数规范化梳理与归集，适配意图识别拆分、分支器分流等各类多分支工作流场景，是简化复杂流程配置、规范参数传递逻辑的核心辅助组件。

### 参数聚合节点核心价值

### 统一参数入口，简化下游配置

针对多分支工作流中不同分支输出参数类型、名称、来源不一致的问题，通过参数聚合节点将分散的分支输出整合为单一标准化参数，下游节点无需针对每条分支单独配置参数引用路径，仅需对接聚合后的统一参数即可，彻底简化下游节点的参数配置流程，降低操作难度。

### 适配分支动态切换，保障流程稳定性

工作流分支执行具有随机性与动态性，仅某一条分支会根据业务条件触发运行，参数聚合节点可自动识别并捕获当前有效分支的输出结果，忽略未执行分支的空参数，确保无论哪条分支运行，下游节点都能稳定获取有效数据，避免因分支切换导致的参数缺失、流程中断问题，提升整体工作流运行稳定性。

以下为一个作业辅导 Agent 工作流示例，在此工作流设计中，意图识别节点会首先分析用户输入的问题，自动判断其所属的学科类别（例如语文、数学或英语）。根据识别结果，问题将被分支到相应的学科进行处理。比如，语文问题会交给扮演“语文老师”的大模型节点来生成答案。每个学科分支（如语文老师、数学老师、英语老师节点）都会产生两个输出参数：

Final\_answer：聚合后的最终答案。

Final\_class：聚合后的课程类型。

最终，Final\_answer 和 Final\_class 这两个参数会被传递至结束节点，作为工作流的最终输出结果返回给用户。（说明：聚合输出参数名可根据业务需求自定义，建议简洁且贴合业务含义。）

## 3. 结束节点

### 3.1 结束节点概述

结束节点是百度千帆智能体工作流的最终输出节点，负责输出应用运行后的最终结果，是用户直接看到的内容，其配置效果直接决定智能体的用户体验。

结束节点无后续连接节点，所有工作流的业务逻辑最终均汇聚至该节点，核心配置为回复模式选择和输出参数+ 模板配置，需根据实际业务场景选择适配的配置方式。

### 3.2 参数配置

回复模式：

3. 结构化数据输出场景（如 API 调用），选择【直接返回参数值】模式，便于下游系统解析

4. 可在模板中添加基础引导语（如 “为你解答如下：”）、表情符号（如☀、❄），提升亲和力。

## 4. 工作流 Agent 之预览与调试

调试是工作流开发的关键环节，用于验证节点配置、参数传递、分支执行的正确性，快速定位并解决问题。百度千帆平台支持单节点调试和整体调试两种方式，适配不同的调试场景，调试完成后即可发布智能体。

### 4.1 整体调试

### 适用场景

验证工作流全流程逻辑的正确性，包括节点连接、参数联动、分支触发、多节点协作等，适用于所有节点配置完成后的整体验证。

### 操作步骤

1. 工作流所有节点配置完成后，点击画布中【调试】按钮，打开调试预览窗口

2. 在输入框中输入测试问题（如 “北京的天气怎么样？”），点击发送，测试问题将传入开始节点的系统参数【rawQuery】中

3. 平台将自动执行整个工作流，在调试窗口输出结束节点的最终结果

4. 可查看工作流执行日志，了解每个节点的执行状态、参数传递值、是否执行成功，定位流程中断或结果错误的原因

![](baidu_images/9287cfb37bbbf784dc6c5139c20e8271ddd5b2f91cb38851967309e5143147f8.jpg)

### 4.2 单节点调试

### 适用场景

验证单个功能节点的配置正确性，无需执行整个工作流，适用于节点配置过程中的即时验证，提升开发效率。

### 支持的节点类型

大模型、智能体、API 节点、MCP Server、CFC（云函数计算，Cloud Function Compute）、意图识别、数据库、代码、知识库、循环、文本处理（其余节点如参数聚合、记忆变量、全局跳转等依赖上下文，需在整体调试中验证）。

### 操作步骤

1. 配置完单个节点的信息后，点击节点右上角【调试】按钮，打开节点调试窗口

2. 按节点要求填写测试入参（如大模型节点填写测试 rawQuery，API 节点填写测试参数）

3. 点击【开始运行】，查看节点的输出结果，验证配置是否正确

4. 若结果不符合预期，直接在节点面板修改配置，再次调试，直至结果正确

![](baidu_images/aab8f6bde84404f42cc7848b7336cc9a599ba2e3d289807a9e636d7ba6df5e02.jpg)

![](baidu_images/d20d4acb32ea4878e5b0f1e699acc7d86293018f40d8d4207af74d299ac329a3.jpg)

### 4.3 调试核心技巧

结果为空：检查参数引用路径是否正确，节点连接是否无误，聚合节点的聚合参数是否添加完整

API 调用失败：检查接口 URL、请求方式、参数配置是否与接口文档一致，API 密钥是否有效，网络是否通畅

分支触发错误：检查分支器的判断条件、意图识别节点的配置是否正确，意图参数是否传递无误

大模型结果不符：优化大模型节点的提示词，明确角色任务、输出要求，更换适配的模型进行测试。

### 4.4 发布配置

完成应用配置和效果调试后，可点击右上角【发布】按钮，进行多渠道发布并支持创建API调用密钥。

【实践】： "千帆平台智能客服小助手" 调试与发布

### 全流程调试

依次测试三个业务分支的功能：

产品问题：输入 “百度千帆平台是做什么的？”，验证产品问题解答分支是否触发，答案是否准确

非产品问题：输入 “什么是马斯洛需求层次理论？”，验证非产品问题解答分支是否触发，总结结果是否合理

天气查询：输入 “北京今天天气如何？”，验证天气查询分支是否触发，天气信息是否准确

若某一分支结果错误，通过【执行日志】定位问题节点（如 API 节点调用失败、大模型提取参数错误），单独调试该节点并修改配置

所有分支测试通过后，完成多轮对话调试（如 “杭州的天气？”→“明天呢？”），验证上下文连贯性

### 智能体发布

所有调试通过后，点击平台右上角【发布 v1】按钮，完成智能体的首次发布

发布后若对工作流进行了配置更新，再次点击右上角【更新发布 v2】，实现版本迭代
