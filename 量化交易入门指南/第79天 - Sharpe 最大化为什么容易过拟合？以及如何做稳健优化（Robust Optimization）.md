# 量化交易进阶:第79天 - Sharpe 最大化为什么容易过拟合？以及如何做稳健优化（Robust Optimization）

原创 逻辑与流 逻辑与流 2026年4月7日 19:48 北京 听全文

很多人第一次把组合构建“写成一个目标函数”时，都会被 Sharpe 最大化惊艳到：回测里它经常给出一个看起来非常漂亮的解——收益高 波动低 Sharpe 爆表

但实盘里你很快会遇到同一个问题：为什么很多“看起来最优”的组合，一上样本外就崩？

这不是你写错了优化器，而是 Sharpe 最大化本身有一个天然陷阱：它会把“估计误差”当成“可利用的信号”，从而得到最不稳定的最优解

一句话结论：Sharpe 最大化 = 对未来收益的强假设 + 对历史噪声的过度拟合，因此“最优解往往是最不稳定的解”<sub>。</sub>

为什么会崩： w\* ∝ Σ^{-1} μ 里，μ 和 Σ 都是噪声估计；一旦估计有误，Σ^{-1} 会放大误差，优化器会把权重压向“最会利用噪声的方向”

怎么变稳：不追求最优，而追求稳定的次优——加约束（权重/换手） 做收缩（cov/return shrinkage）加正则（L2）<sub>、</sub>用 BL<sub>、</sub>滚动更新<sub>、</sub>Bootstrap 平均权重<sub>。</sub>

你现在可做：风险平价或等权打底，再做小幅 Sharpe 微调，并配合 shrinkage + 权重上限 + 换手约束<sub>。</sub>

先把结论钉死，再解释“为什么”，最后给你一套可以直接照抄的稳健版本配置 这样你读完就能改你现有的组合优化模块，而不是停留在概念层

## 一 先给结论（最重要）

Sharpe 最大化 = 对“未来收益”的强假设 + 对“历史噪声”的过度拟合

所以在实盘里常见的结果是：

你拿到的“最优解”，往往也是对估计误差最敏感 最不稳定的解

回测 Sharpe 看起来很高，但样本外很快掉下来，甚至风格完全变形

有了这个结论，下面我们从公式开始，把它为什么“天然容易过拟合 ”讲透

## 二 Sharpe 最大化为什么会过拟合？

经典目标是：

$$
\max _ {w} \frac {w ^ {\top} \mu}{\sqrt {w ^ {\top} \Sigma w}}
$$

在均值-方差框架里，最优方向等价于：

$$
w ^ {*} \propto \Sigma^ {- 1} \mu
$$

问题就出在这两件事： $\mu$ 不稳 Σ 不稳，而且 $\Sigma ^ { \wedge } \{ - 1 \}$ }会把不稳放大

## 1) μ（收益）是最不稳定的量

现实里你用的几乎都是：

历史平均收益

但真实世界更接近：

未来收益 ≠ 历史收益

样本常常很短（比如 6–12 个月）

收益噪声很大（波动 跳跃 风格切换）

所以 $\mu$ 的估计误差往往是巨大的 优化器会把这点误差当成“确定信号”，并把权重压到“历史上看起来最强”的标的或子策略上

举个极简例子（你会在权重里看到同样的现象）：

历史样本：

<table><tr><td>Universe</td><td>年化收益(估计)</td></tr><tr><td>A</td><td>10%</td></tr><tr><td>B</td><td>11%</td></tr><tr><td>C</td><td>9%</td></tr></table>

如果 B 的 11% 只是运气好，Sharpe 最大化依然会倾向给它极高权重，例如：

$$
w \approx [ 0. 1, 0. 8, 0. 1 ]
$$

于是只要 B 回归均值，你的组合就会出现“回测最优 实盘崩”的典型断层

## 2) Σ（协方差）也有估计误差，且逆矩阵放大误差

协方差矩阵 Σ 的估计问题在高维时尤其严重：

样本少（T 不大）

维度高（N 不小）

协方差结构随时间变化（相关性在危机/拥挤时会跳）

更致命的是：Sharpe 解里要用 Σ^{-1}<sub>。</sub>

直觉上你可以这样记：

## Σ 的一点点误差，经过求逆会被放大成很大的权重差异

所以你会看到：

权重剧烈波动

权重莫名其妙极端集中

小改数据窗口（多一个月/少一个月）解就完全变了

## 3) 最深层原因：最优解往往落在“噪声方向”

Sharpe 最大化本质是在找一个方向，让“收益/波动”最大

但在历史数据里同时存在两类东西：

真实信号（alpha）

随机噪声（偶然性）

优化器不会区分它们，它只会最大化目标函数

于是很容易出现这样的现象：

你找到的不是“最真实的 alpha”，而是“最会利用样本噪声的组合”

这就是“回测 Sharpe 很高”的来源，也是“样本外迅速掉下来”的根因

## 三 过拟合的典型表现（你一眼就能对照）

## 1) 权重极端集中

例如：

[0.05, 0.90, 0.05]

这通常不是“你发现了一个 90% 确定的 alpha”，而是“优化器找到了一条最会利用估计误差的路径”

## 2) 权重不稳定（对窗口极敏感）

每次重新估计：

上个月：A 最大

这个月：B 最大

如果你的组合构建是“每月重算一次 Sharpe 最优”，你会得到高换手 + 高漂移的组合

## 3) 回测极好 → 实盘崩

经典断层：

回测 Sharpe = 2.5

实盘/样本外 $\mathrm { S h a r p e } = 0 . 5$

注意：这不是“市场变差了”，而是你的组合本身对估计误差过度敏感

## 四 如何做稳健优化（Robust Optimization）

核心思想只有一句话：

不追求最优，而追求稳定的次优

下面给你一套从“最容易落地”到“机构级”的工具箱；你不需要全用，但至少要用其中的几类，让优化器从“利用噪声”变成“对抗噪声”

## 1) 限制权重（最简单也最有效）

加硬约束，例如：

$$
0 \leq w _ {i} \leq 0. 5
$$

## 效果很直接：

防止集中

让解空间变得更“圆滑”，权重更稳定

很多实盘里，这一个改动就能显著降低崩盘概率

## 2) 协方差收缩（Shrinkage）

当 Σ 不稳定时，用收缩把它往“更保守 更简单”的结构拉：

$$
\Sigma_ {\text { shrink }} = (1 - \lambda) \Sigma + \lambda I
$$

直觉：

λ 越大，越不相信样本协方差的细节

相关性的“噪声结构”会被抹平一些，求逆更稳定

示例代码：

$$
\text {import numpy as np}
$$

$$
\text { def   } \text { shrink\_cov } (\text { cov:   np.ndarray,   alpha:   float   =   0.2 }) \to \text { np.ndarray: }
$$

$$
I = n p. e y e (c o v. s h a p e [ 0 ])
$$

$$
\text { return } (1 - \text { alpha }) * \text { cov } + \text { alpha } * I
$$

## 3) 对 μ 做收缩（很多时候更关键）

你要明确一件事：μ 常常比 Σ 更不可信

一种简单可用的写法是把 μ 往一个“更保守的先验”拉：

$$
\mu_ {\mathrm{shrink}} = (1 - \lambda) \mu + \lambda \bar {\mu}
$$

其中 μ̄（mu-bar）可以是：

全市场/全资产的均值

你设定的一个常数（更保守）

极端一点，你甚至可以直接把 $\mu$ 设为常数（等收益假设），优化就更接近：

风险最小化 / 风险平价风格的解

这在很多“预测 $\mu$ 很难”的场景下反而更稳

## 4) 加正则化（非常重要，等价于“惩罚极端权重”）

把目标改成：

$$
\max _ {w} \biggl (\frac {w ^ {\top} \mu}{\sqrt {w ^ {\top} \Sigma w}} - \lambda \| w \| ^ {2} \biggr)
$$

作用：

惩罚极端权重

让权重更平滑 更稳定

你可以把它当作机器学习里的 L2 正则：不是为了回测最优，而是为了样本外更稳

5) Black-Litterman（机构级：把“先验 + 观点”写进来）

核心思想是：μ 不直接用历史均值，而是：

市场均衡收益（先验）

你的观点（views）

融合得到一个更稳的 μ<sub>。</sub>

它的实务优势是：

不容易出现极端权重

可以把“我只对少数观点有信心”表达出来

很多机构会把 BL 当作“稳健的默认选项”，而不是把历史均值当真值

## 6) 滚动窗口 + 稳定性/换手约束（把“可执行性”写进优化）

不要一次算一个“永恒最优”：

每月/每周滚动更新

并把“不要剧烈变动”写成约束，例如：

$$
\| w _ {t} - w _ {t - 1} \| _ {1} \leq \tau
$$

或更简单的逐元素阈值：

$$
\left| w _ {t, i} - w _ {t - 1, i} \right| \leq \epsilon
$$

这会同时带来两件好处：

降低换手与成本

把噪声导致的“权重跳变”压下去

## 7) Bootstrap（非常强：用重采样对抗噪声）

## 思路是：

重采样历史数据（bootstrap）

多次优化得到多组权重

对权重取平均（或中位数）

示意代码：

import numpy as np

def bootstrap\_weights(returns, optimize\_fn, n=100, rng=None):

rng = np.random.default\_rng(rng)

T = returns.shape[0]

$$
w s = [ ]
$$

idx = rng.integers(0, T, size=T)

sample = returns[idx]

ws.append(optimize\_fn(sample))

return np.mean(np.vstack(ws), axis=0)

本质上你是在问一个更稳的问题：

“在很多可能出现的历史样本下，这个组合还好吗？”

而不是只在一个固定样本上追求最优

## 五 最实用的一套组合（可以直接用）

如果你只想要一套“稳健版本 Sharpe 优化”的默认配置，可以直接用这套：

1. 用 shrinkage covariance

2. 对 μ 做弱化（收缩，甚至不用 μ）

3. 加权重上限（例如单资产 ≤ 50% 或更低）

4. 每月滚动更新

5. 加换手/权重变化约束

更简单的实盘路径是：

风险平价 + Sharpe 微调，而不是纯 Sharpe 最大化<sub>。</sub>

你可以把它理解成：

先用“稳”的方法定骨架

再用“进攻”的信息做小幅倾斜

## 六 一个非常重要的认知（把坑一次避开）

Sharpe 最大化的问题不在公式本身，而在于你把 μ 与 Σ 当成“真值”：

以为 μ 和 Σ 是真值，其实它们是带噪的估计

一旦你接受这一点，你会自然把优化目标从“最优”改成“稳健”，把工程重心从“求解器”转到“估计误差管理”<sub>。</sub>

## 七 应该怎么用（正确路径）

不要用纯 Sharpe 最大化当默认配置 更合理的顺序是：

Step 1：先用等权 / 风险平价打底

先保证组合结构稳定<sub>、</sub>可执行<sub>、</sub>不过度依赖 μ<sub>。</sub>

用你更可信的信号（更长样本 更强先验 更少自由度）做小幅偏移

## Step 3：把稳健手段补齐

至少加上：

shrinkage

rolling

权重上限 / 换手约束

## 八 最后一句（非常重要）

在量化里：

“最优解通常是最危险的解 ”

“稳定的次优解，才是能赚钱的解 ”

## 结论

Sharpe 最大化之所以在回测里常常“看起来最优”，却在样本外容易失效，根因在于它对 μ（收益）与 Σ（协方差）这两类噪声估计过度敏感：μ 本身极不稳定，而 Σ^{-1} 会放大协方差估计误差，优化器还会天然倾向于把权重压到“最会利用噪声的方向”，最终表现为权重极端集中 对窗口极敏感 回测好但实盘崩

稳健优化的正确心法是不追求最优 而追求稳定的次优：用权重与换手约束控制解空间，用协方差/收益收缩与正则化降低误差放大效应，用滚动更新与 Bootstrap 让权重对样本扰动更不敏感；更机构级的做法则用 Black-Litterman 把先验与观点融合成更稳的 μ 落地上最推荐的路径是“风险平价（或等权）打底 + Sharpe 微调”，再配合 shrinkage 与约束，让组合从“回测最优”走向“样本外可活”
